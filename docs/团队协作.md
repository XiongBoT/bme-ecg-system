# 任务与发布记录

## 任务认领

所有成员均可认领任何模块；负责人仅表示正在推进该任务，不限制其他人的修改权限。使用 GitHub Issues 和 PR 维护实时状态，避免本表成为第二套过期任务列表。

开工前按任务模板写明目标、预计修改路径、任务分支、验收条件，并查看未完成的 Issue/PR。预计路径用于发现重叠，不是永久文件归属。需求扩大到新文件或共享接口时，先更新 Issue，再继续相应修改。

| 并行情形 | 协调方式 |
| --- | --- |
| 不同文件且接口独立 | 各自使用独立分支和工作目录；分别提交小范围 PR |
| 同一文件、不同功能 | 在双方任务中注明相关 PR 与各自修改位置；可先开 Draft PR 展示差异，约定合并顺序 |
| 同一段代码或同一接口 | 先约定一项任务完成共同部分，后续任务同步 main 后继续；也可拆分实现与测试范围，避免双方各改一套接口 |
| 临时变更、暂停或交接 | 在原 Issue 更新进度、分支与未完成项；需要调整顺序时重新协调，不复制整个工程覆盖对方工作 |

共享的 README、依赖清单、接口约定和工作流同样需要协调。一般冲突在任务分支逐处解决并复验；不能仅因 Git 可以自动合并就认定两个行为兼容。主分支强制条件统一见[协作质量与发布](协作质量与发布.md#main-的保护目标)，日常操作见[贡献指南](../CONTRIBUTING.md#每个任务的操作)。

| 工作 | 建议验收内容 |
| --- | --- |
| 新成员环境 | 完成克隆、依赖安装及相关检查，提交一个小 PR |
| 固件与串口 | Keil 编译通过，板端与终端协议一致，异常帧处理可验证 |
| 终端功能 | 模拟/回放下启动、保存、历史记录功能正常 |
| 云端功能 | 账号、设备、记录归属与后台任务测试通过 |
| Windows 电脑端交付 | 构建压缩包、中文路径解压并实际启动，确认真实 HTTPS 登录入口及未登录访问限制；不携带记录或凭据 |
| 完整联调 | 指定版本完成实体板采集、保存、上传和网页回看 |

## 成员邀请

尚未提供成员名单；邀请时使用 GitHub 用户名或注册邮箱，接受邀请后可修改整个仓库。没有仅限文档或仅限某个目录的成员角色。

## 发布记录模板

| 字段 | 填写内容 |
| --- | --- |
| 日期与执行人 | 实际操作时间、成员 |
| 提交编号 | `git rev-parse HEAD` |
| 目标 | 指定 STM32、树莓派或云服务器 |
| 升级前版本 | 可回退的提交或备份标识 |
| 验证 | 编译、软件检查、板上检查及未完成事项 |
| 回退 | 恢复哪个版本及如何操作 |

合并 PR 不代表已部署。发布记录不填写服务器密码或设备密钥。

电脑端免安装入口的构建与使用见 [电脑端说明](../心电云端平台/deploy/desktop/README.md)，阶段验收及剩余工作统一维护在 [云端工作台迭代](../心电云端平台/docs/云端工作台迭代.md)。生成的 ZIP/EXE 不提交源码仓库；本地交付不等同于 GitHub Release 发布或云端升级。
