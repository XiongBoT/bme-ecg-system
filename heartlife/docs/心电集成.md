# 心伴与心电平台连接

[心伴首页](../README.md) · [共同接口](../../docs/接口约定.md) · [交付状态](../../docs/版本与交付状态.md)

心伴与心电平台各自保存账号、会话和数据库；用户在两端登录后主动绑定。绑定后可查看本人摘要及私密心电周报，另行授权后可在心伴发起固定时长测量。设备权限、实际采集、波形、分类及 QRS/RR 分析仍由心电平台负责，生活日记、习惯计划与社区仍由心伴负责。

2026-11-27 已将心电云端、心伴后端和生产前端统一部署为 `6ac70ff3`，集成配置及 HTTPS 检查通过；真实账号登录、绑定和实体设备测量仍待验收。在线入口为[心电工作台](https://62.234.150.104/)与[心伴](https://62.234.150.104/heartlife/)，部署方法见[统一部署](../../docs/统一部署.md)。

新安装默认关闭集成。已有公开 APK 不会因服务器或仓库更新而获得新增的内置入口；本次没有发布新 APK，以下流程先从浏览器网页进入，同签名 APK 更新及实体手机验收另行记录。

## 用户流程

1. 在浏览器打开心电工作台，从「我的」进入心伴连接，确认当前心电账号；在心伴使用本人的独立账号登录。
2. 阅读摘要授权范围；若需要从心伴发起测量，另行勾选测量权限，默认不勾选。生成的一次性绑定码五分钟有效，只在本人已登录的心伴账号中使用。
3. 在心伴「心电记录」粘贴绑定码并确认关联。不要输入或转交心电密码；同名账号不会自动合并。
4. 查看本人最近五条已完成记录、日/月/年趋势及周报中的私人心电统计；点击记录进入原心电工作台，按原平台权限登录并查看详情。
5. 已授予测量权限时，选择本人已授权且就绪的设备，提交 1 / 3 / 5 分钟测量。页面分别显示采集、上传及分析状态；设备仍须由现场人员正确连接并准备好。
6. 在任一端解除关联。心伴解绑立即隐藏数据；远端不可用时显示待撤销，可稍后重试。心电端可以直接撤销，包括兑换响应丢失留下的关联。解绑阻止后续桥接操作，不等于取消已经下发的采集任务。

授权有效期三十天，过期需重新绑定。心电账号停用、密码修改/重置或撤销全部会话会撤销关联；重新启用账号不会恢复旧授权。普通退出登录不自动解除跨服务授权，需使用「解除关联」。

旧绑定保持只读。需要测量时，先解除旧关联，再在心电授权页明确勾选并重新绑定；心伴不能在兑换时自行申请更高权限。这里的定时测量是固定时长，不是每日定点自动开始。

## 数据范围

| 数据 | 心伴是否读取 | 说明 |
| --- | --- | --- |
| 心电账号标识与账号名 | 是 | 用于核对绑定对象，不共享密码或会话 |
| 最近记录编号、采集时间、时长、终端平均心率 | 是 | 仅本人、串口来源、上传完成、未回收的记录 |
| 日/月/年次数、时长与心率趋势 | 是 | 复用心电平台原趋势计算；缺失心率为 `null` |
| 本人一周测量次数、总时长与终端心率 | 是 | 独立私密接口，按账号时区逐日统计，不进入家庭共享或生活助手 |
| 波形、备注、分类和 QRS/RR 结果 | 否 | 进入原工作台查看；仍需原平台登录 |
| 本人可用设备、测量请求与任务状态 | 另行授权后 | `measurement_allowed=true`，每次仍检查有效绑定与设备权限 |
| 设备授权及管理员操作 | 否 | 在原平台由管理员完成；桥接不继承管理员的全设备可见范围 |
| 社区、家庭共享与生活助手使用心电数据 | 否 | 本轮没有自动接入这些功能 |

心率来自终端质量合格窗口的摘要，不是云端 QRS 的计算结果。趋势按心伴账号时区在所选日期的 UTC 偏移聚合；当前心电接口使用固定偏移，跨夏令时切换的整月/整年不会逐日改变偏移。未记录的数据不填零；上传完成不表示算法分析完成。

心电周报使用独立的时区计算：一周从账号本地周一开始，逐日本地午夜换算 UTC，可处理夏令时变化；本周只计截至今日，未来日期不解释为漏测。次数与时长统计本人已上传完成、串口来源、未回收记录；心率按有效窗口采样数加权，不平均已经四舍五入的每日均值。无心率显示「尚无有效心率」，不能补成 0。生活周报和心电周报分别请求，任一服务故障不覆盖另一份已加载内容。

## 服务端接口

### 心电平台

| 接口 | 身份与用途 |
| --- | --- |
| `GET /api/heartlife/link` | 当前心电用户查看自己的关联 |
| `POST /api/heartlife/link-code` | 当前用户与 CSRF 校验，生成五分钟绑定码；可选正文 `{"measurement_allowed":true}`，省略时只读 |
| `DELETE /api/heartlife/link` | 当前用户与 CSRF 校验，撤销本人的全部关联及未消费码 |
| `POST /api/heartlife/exchange` | 配置的心伴客户端兑换码，绑定不可变心伴用户 ID 与操作编号 |
| `GET /api/heartlife/summary` | 客户端密钥、授权令牌及对应心伴用户 ID；返回白名单摘要 |
| `GET /api/heartlife/devices` | 额外测量权限；只返回本人被授权设备的名称、在线/就绪状态与固定原因文案 |
| `GET /api/heartlife/measurements` | 额外测量权限；本人最近测量请求及独立分析状态 |
| `POST /api/heartlife/measurements` | 额外测量权限；复用原测量服务及事务，不使用通用用户会话 |
| `GET /api/heartlife/weekly-summary` | 摘要权限；查询参数 `week_start`（周一）、`timezone`（IANA）、`observed_days`（1–7） |
| `DELETE /api/heartlife/grant` | 客户端与对应令牌/用户 ID，撤销指定授权 |
| `DELETE /api/heartlife/subject-grant` | 客户端、心伴用户 ID 和绑定操作编号，恢复处理丢失的兑换响应 |

服务端客户端密钥通过 `X-HeartLife-Key` 传递；摘要令牌使用 `Authorization: Bearer …`，身份使用 `X-HeartLife-Subject`。恢复撤销还校验 `X-HeartLife-Operation`，防止迟到的旧解绑请求撤销新绑定。

绑定码至少 128 bit 随机强度，在事务中一次性消费；心电数据库仅存绑定码和授权令牌的 SHA-256 摘要。双方绑定唯一，不自动覆盖旧授权。此令牌不能用于原平台通用 API、设备上传或管理员接口。

`measurement_allowed` 在生成绑定码时确定并随兑换保存，旧表新增字段的默认值为 `false`。客户端声明、界面按钮或管理员角色均不能替代此权限。测量写入在同一事务中重查绑定、用户有效性及设备接收权限。

### 心伴

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/me/ecg/link` | 启用、关联及待撤销状态 |
| `POST /api/v1/me/ecg/link` | 提交绑定码；用户 ID 从当前会话取得 |
| `GET /api/v1/me/ecg/summary?period=day&anchor=2026-11-26` | 本人摘要；偏移由个人时区计算 |
| `GET /api/v1/me/ecg/devices` | 本人授权设备；需额外测量许可 |
| `GET /api/v1/me/ecg/measurements` | 本人测量与报告状态；需额外测量许可 |
| `POST /api/v1/me/ecg/measurements` | `device_id`、`duration_s`（60/180/300）、`request_key`（UUID） |
| `GET /api/v1/me/ecg/weekly-summary?week_start=2026-11-23` | 独立私密周报；省略日期为本周，时区与有效天数由账号设置计算 |
| `DELETE /api/v1/me/ecg/link` | 隐藏数据并撤销；失败时保留待重试状态 |

接口均要求心伴登录，写操作校验 CSRF。授权令牌只保存在心伴服务端数据库，不进入前端、个人导出、日志或链接。数据库备份同样视为敏感配置，保持目录 `700`、配置文件 `600`，不提交到 Git。

心伴先持久保留绑定操作，再请求兑换。兑换结果不确定时保留待清理状态，等待五分钟码窗口及网络余量结束后重试清理；此期间不展示摘要或开始新绑定。注销账号先验证密码并完成远端撤销；撤销失败时保留账号并提示重试，避免把未完成的跨服务撤销写成成功。

### 测量及周报约定

设备、测量和周报响应均携带 `ecg_user` 与 `expires_at`，心伴验证绑定对象及请求周期。设备字段限于 `device_id`、`label`、`online`、`ready`、`reason`，不公开原始心跳、其他采集者或设备管理信息。

测量提交和原平台保持相同规则：心跳须在 35 秒内，设备为待机且声明可远程测量，没有占用中的请求；新任务有 45 秒领取期限。同一账号相同 `request_key` 只产生一个请求，改变设备或时长则返回冲突。响应丢失时重试原键与原参数，不重新生成键；提交成功后可重新打开页面获取任务进度。当前标签页仅暂存待确认的设备、时长及请求键，按账号和当前绑定隔离，不保存令牌、波形或报告；成功、确定拒绝、换号或解绑后清理。

测量响应使用 `measurement` 或 `measurements`，每项保留原任务字段，并增加 `report.model` 与 `report.physiology`：

| 状态 | 含义 |
| --- | --- |
| `not_started` | 尚未分析，或已有结果不再适用于当前记录 |
| `queued` / `running` | 分析排队 / 正在运行 |
| `completed` | 该分析结果存在且仍有效 |
| `failed` | 分析失败，可进入原工作台处理 |
| `ineligible` | 不满足该分析条件 |

任务 `status=completed` 仅指上传完成。心伴不会自动开启原账号的自动分析，也不把尚未分析的记录标成报告完成；报告入口仍为原工作台 `/?record=<session_id>`。页面只显示固定友好状态，不转发后台错误原文。

心电周报字段为 `week_start`、`week_end`、`timezone`、`observed_days`、`total_records`、`total_duration_s`、`hr_mean`、`hr_records` 及七项 `daily_series`；每日字段为 `date`、`records`、`duration_s`、`hr_mean`、`hr_records`。此数据不合入共享的生活周报服务，也不自动加入家庭、社区、助手或个人导出。

## 同一站点及 Android 配置

推荐路径为原工作台 `/`、心伴 `/heartlife/`。心伴保持监听 `127.0.0.1:8010`，原心电服务保持 `127.0.0.1:8766`。前端通过 `/heartlife/api/v1/…` 访问心伴，不与原 `/api/…` 路由混用。

在部署前备份两个数据库和配置，记录双方源码提交及回退目录。以下值是配置说明，密钥必须现场生成，不能使用示例文本作为实际密钥。

| 配置位置 | 变量 | 同机配置 |
| --- | --- | --- |
| 心电服务环境 | `ECG_AUTH_REQUIRED` | `1` |
| 心电服务环境 | `ECG_HEARTLIFE_URL` | `https://你的心电站点/heartlife/` |
| 心电服务环境 | `ECG_HEARTLIFE_CLIENT_SECRET` | 随机密钥，至少 32 字符 |
| 心伴环境 | `ECG_EXTERNAL_URL` | `https://你的心电站点/` |
| 心伴环境 | `ECG_API_BASE_URL` | `http://127.0.0.1:8766` |
| 心伴环境 | `ECG_CLIENT_SECRET` | 与心电服务的客户端密钥相同 |
| 心伴环境 | `FRONTEND_ORIGIN` | `https://你的心电站点` |
| 心伴环境 | `COOKIE_SECURE` | `true` |
| 心伴环境及前端构建 | `COOKIE_PATH`、`VITE_BASE_PATH` | 两者均为 `/heartlife/` |

启用变量默认留空；只配置外部链接时仍可使用原跳转方式。跨主机的服务端接口必须使用 HTTPS；仅明确的本机回环地址允许 HTTP。浏览器不能传入接口地址，服务端不跟随重定向或读取代理环境变量。

1. 在心伴环境文件填写上述配置，重新构建前端并迁移数据库；安装脚本在构建前读取环境文件。
2. 在原 HTTPS Nginx `server` 块内加入 [子路径配置](../deploy/tencent-cloud/nginx-heartlife-subpath.conf)，保留原心电路由。代理仅去掉 `/heartlife/` 前缀。
3. `nginx -t` 通过后重载，再启动/重启两项服务。生产环境不公开 8010/8766 端口。
4. 检查 `/heartlife/`、刷新 `/heartlife/ecg`、静态资源和 `/heartlife/api/v1/health`；再用两个合成测试账号完成只读绑定、明确测量授权、本人摘要与周报、解绑与断网恢复。

第二轮升级须在心伴环境执行数据库迁移；心电服务启动时兼容添加许可字段。先升级两个服务再开放新界面，旧绑定不会自动获得测量权限。实体测量验收需另外连接 STM32 与树莓派，软件模拟不能替代。

## 检查与交付

在两个 Python 工程分别执行，避免同名导入冲突：

```bash
cd 心电云端平台
python -m unittest discover -s tests -p 'test_heartlife_bridge.py' -v
python -m unittest discover -s tests -p 'test_heartlife_measurement.py' -v
cd ../heartlife/backend
python -m pytest -q
cd ../frontend
npm ci
npm run test -- --run
VITE_BASE_PATH=/heartlife/ npm run build
```

GitHub Actions 的 `HeartLife integration` 纳入统一 `Quality gate`，覆盖心伴后端、真实心电接口契约、前端测试与子路径生产构建。测试均使用合成账号和隔离数据，不能替代部署或真实手机验收。第一轮见 [PR #84](https://github.com/XiongBoT/bme-ecg-system/pull/84)，第二轮结果在[任务 #85](https://github.com/XiongBoT/bme-ecg-system/issues/85) 对应 PR 与[进度台账](progress.md)记录。

出现问题时先关闭心伴入口与集成配置，再按升级前提交恢复代码、重建相应路径的前端；两个数据库分别按各自备份恢复。不要把心伴数据库改指向心电数据库，不以共享 Cookie 或关闭原平台认证解决连接问题。
