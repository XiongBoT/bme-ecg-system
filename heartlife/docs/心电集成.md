# 心伴与心电平台连接

[心伴首页](../README.md) · [共同接口](../../docs/接口约定.md) · [交付状态](../../docs/版本与交付状态.md)

本轮连接入口、账号授权及本人只读摘要。心伴与心电平台各自保存账号、会话和数据库；用户在两端登录后主动绑定。测量控制、波形、分类及 QRS/RR 分析仍由心电平台负责，生活日记、习惯计划与社区仍由心伴负责。

源码集成不等于已部署。已有公开 APK 不会因服务器或仓库更新而获得新增的内置入口；正式部署、同签名 APK 更新及实体手机验收另行记录。

## 用户流程

1. 在心电健康助手的「我的」打开心伴连接，确认当前心电账号。
2. 阅读只读授权范围，生成一次性绑定码。绑定码五分钟有效，只在本人已登录的心伴账号中使用。
3. 在心伴「心电记录」粘贴绑定码并确认关联。不要输入或转交心电密码；同名账号不会自动合并。
4. 查看本人最近五条已完成记录、日/月/年趋势；点击记录进入原心电工作台，按原平台权限登录并查看详情。
5. 在任一端解除关联。心伴解绑立即隐藏摘要；远端不可用时显示待撤销，可稍后重试。心电端可以直接撤销，包括兑换响应丢失留下的关联。

授权有效期三十天，过期需重新绑定。心电账号停用、密码修改/重置或撤销全部会话会撤销关联；重新启用账号不会恢复旧授权。普通退出登录不自动解除跨服务授权，需使用「解除关联」。

## 数据范围

| 数据 | 心伴是否读取 | 说明 |
| --- | --- | --- |
| 心电账号标识与账号名 | 是 | 用于核对绑定对象，不共享密码或会话 |
| 最近记录编号、采集时间、时长、终端平均心率 | 是 | 仅本人、串口来源、上传完成、未回收的记录 |
| 日/月/年次数、时长与心率趋势 | 是 | 复用心电平台原趋势计算；缺失心率为 `null` |
| 波形、备注、分类和 QRS/RR 结果 | 否 | 进入原工作台查看；仍需原平台登录 |
| 发起测量、设备授权与管理操作 | 否 | 本轮授权只有 `summary:read` |
| 社区、家庭共享与生活助手使用心电数据 | 否 | 本轮没有自动接入这些功能 |

心率来自终端质量合格窗口的摘要，不是云端 QRS 的计算结果。趋势按心伴账号时区在所选日期的 UTC 偏移聚合；当前心电接口使用固定偏移，跨夏令时切换的整月/整年不会逐日改变偏移。未记录的数据不填零；上传完成不表示算法分析完成。

## 服务端接口

### 心电平台

| 接口 | 身份与用途 |
| --- | --- |
| `GET /api/heartlife/link` | 当前心电用户查看自己的关联 |
| `POST /api/heartlife/link-code` | 当前用户与 CSRF 校验，生成五分钟绑定码 |
| `DELETE /api/heartlife/link` | 当前用户与 CSRF 校验，撤销本人的全部关联及未消费码 |
| `POST /api/heartlife/exchange` | 配置的心伴客户端兑换码，绑定不可变心伴用户 ID 与操作编号 |
| `GET /api/heartlife/summary` | 客户端密钥、授权令牌及对应心伴用户 ID；返回白名单摘要 |
| `DELETE /api/heartlife/grant` | 客户端与对应令牌/用户 ID，撤销指定授权 |
| `DELETE /api/heartlife/subject-grant` | 客户端、心伴用户 ID 和绑定操作编号，恢复处理丢失的兑换响应 |

服务端客户端密钥通过 `X-HeartLife-Key` 传递；摘要令牌使用 `Authorization: Bearer …`，身份使用 `X-HeartLife-Subject`。恢复撤销还校验 `X-HeartLife-Operation`，防止迟到的旧解绑请求撤销新绑定。

绑定码至少 128 bit 随机强度，在事务中一次性消费；心电数据库仅存绑定码和授权令牌的 SHA-256 摘要。双方绑定唯一，不自动覆盖旧授权。此令牌不能用于原平台通用 API、设备上传或管理员接口。

### 心伴

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/me/ecg/link` | 启用、关联及待撤销状态 |
| `POST /api/v1/me/ecg/link` | 提交绑定码；用户 ID 从当前会话取得 |
| `GET /api/v1/me/ecg/summary?period=day&anchor=2026-11-26` | 本人摘要；偏移由个人时区计算 |
| `DELETE /api/v1/me/ecg/link` | 隐藏数据并撤销；失败时保留待重试状态 |

接口均要求心伴登录，写操作校验 CSRF。授权令牌只保存在心伴服务端数据库，不进入前端、个人导出、日志或链接。数据库备份同样视为敏感配置，保持目录 `700`、配置文件 `600`，不提交到 Git。

心伴先持久保留绑定操作，再请求兑换。兑换结果不确定时保留待清理状态，等待五分钟码窗口及网络余量结束后重试清理；此期间不展示摘要或开始新绑定。注销账号先验证密码并完成远端撤销；撤销失败时保留账号并提示重试，避免把未完成的跨服务撤销写成成功。

## 同一站点及 Android 配置

推荐路径为原工作台 `/`、心伴 `/heartlife/`。心伴保持监听 `127.0.0.1:8010`，原心电服务保持 `127.0.0.1:8766`。前端通过 `/heartlife/api/v1/…` 访问心伴，不与原 `/api/…` 路由混用。

在部署前备份两个数据库和配置，记录双方源码提交及回退目录。以下值是配置说明，密钥必须现场生成，不能使用示例文本作为实际密钥。

| 配置位置 | 变量 | 同机配置 |
| --- | --- | --- |
| 心电服务环境 | `ECG_AUTH_REQUIRED` | `1` |
| 心电服务环境 | `ECG_HEARTLIFE_URL` | `https://你的心电站点/heartlife/` |
| 心电服务环境 | `ECG_HEARTLIFE_CLIENT_SECRET` | 随机密钥，至少 32 字符 |
| 心伴环境 | `ECG_EXTERNAL_URL` | `https://你的心电站点/` |
| 心伴环境 | `ECG_API_BASE_URL` | `http://127.0.0.1:8766` |
| 心伴环境 | `ECG_CLIENT_SECRET` | 与心电服务的客户端密钥相同 |
| 心伴环境 | `FRONTEND_ORIGIN` | `https://你的心电站点` |
| 心伴环境 | `COOKIE_SECURE` | `true` |
| 心伴环境及前端构建 | `COOKIE_PATH`、`VITE_BASE_PATH` | 两者均为 `/heartlife/` |

启用变量默认留空；只配置外部链接时仍可使用原跳转方式。跨主机的服务端接口必须使用 HTTPS；仅明确的本机回环地址允许 HTTP。浏览器不能传入接口地址，服务端不跟随重定向或读取代理环境变量。

1. 在心伴环境文件填写上述配置，重新构建前端并迁移数据库；安装脚本在构建前读取环境文件。
2. 在原 HTTPS Nginx `server` 块内加入 [子路径配置](../deploy/tencent-cloud/nginx-heartlife-subpath.conf)，保留原心电路由。代理仅去掉 `/heartlife/` 前缀。
3. `nginx -t` 通过后重载，再启动/重启两项服务。生产环境不公开 8010/8766 端口。
4. 检查 `/heartlife/`、刷新 `/heartlife/ecg`、静态资源和 `/heartlife/api/v1/health`；再用两个合成测试账号完成绑定、本人摘要、解绑与断网恢复。

独立域名部署仍支持 `VITE_BASE_PATH=/` 和 `COOKIE_PATH=/`。Android 对原可信来源下的 `/heartlife/` 使用网络页面；其他域名通过系统浏览器打开。心伴页面不取得 Android 的心电凭据自动填入、打印或文件导出权限。旧 APK 仍须更新才能获得新增入口。

## 检查与交付

在两个 Python 工程分别执行，避免同名导入冲突：

```bash
cd 心电云端平台
python -m unittest discover -s tests -p 'test_heartlife_bridge.py' -v
cd ../heartlife/backend
python -m pytest -q
cd ../frontend
npm ci
npm run test -- --run
VITE_BASE_PATH=/heartlife/ npm run build
```

GitHub Actions 的 `HeartLife integration` 纳入统一 `Quality gate`，覆盖心伴后端、真实心电接口契约、前端测试与子路径生产构建。测试均使用合成账号和隔离数据，不能替代部署或真实手机验收。实际执行结果在任务 [#83](https://github.com/XiongBoT/bme-ecg-system/issues/83) 对应 PR 中记录。

出现问题时先关闭心伴入口与集成配置，再按升级前提交恢复代码、重建相应路径的前端；两个数据库分别按各自备份恢复。不要把心伴数据库改指向心电数据库，不以共享 Cookie 或关闭原平台认证解决连接问题。
