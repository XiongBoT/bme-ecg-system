# 云端快速开始

云端导航（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/README.md） · 使用说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/使用说明.md） · 故障排查（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/故障排查.md）

## 使用现有平台

1. 从项目首页（https://github.com/XiongBoT/bme-ecg-system/blob/main/README.md#应用下载）选择网页、Windows 或 Android 下载；iPhone 使用网页，可添加到主屏幕。
2. 使用自己的心电平台账号登录。新版登录页可“申请账号”，管理员通过后使用申请时的密码登录；旧服务没有申请入口或忘记密码时联系项目管理员。GitHub 账号与平台账号分别管理。
3. 由管理员授权采集设备。在树莓派选择同一个使用者，或在手机“开始测量”选择就绪终端与 1／3／5 分钟；实际采集由终端执行，结束后保存上传。
4. 回到工作台刷新，选择记录，核对来源、采集完整性和上传状态，再查看摘要、波形及分析。需要完整数据时导出 CSV。

没有找到记录时，按排查顺序（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/故障排查.md#记录与报告排查）核对账号、上传和筛选；管理员分配账号、设备及历史记录见使用说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/使用说明.md#管理员账号管理待部署）。

账号申请、设备授权与后台地址集中见管理员指南（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/管理员指南.md）。管理员入口为个人工作台的“管理后台”。部署更新后，按“运行总览 → 账号详情 → 管理设备授权 → 查看记录信息”使用，具体步骤见统一管理后台（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/使用说明.md#统一管理后台源码已实现待部署）。

### 先确认使用的是哪个版本

当前公开下载是 Android 1.0.0 试用版，其导航为“记录、结果、账号”。当前 Android 源码为心电健康助手 1.1.0（4），延续“记录、设备、我的”，增加账号申请、登录记忆、日/月/年趋势、固定时长测量和设置；任务中心、统一管理后台与独立 QRS/RR 均已合并。服务器、终端和 APK 需按功能配套更新后使用。各端状态统一见版本与交付状态（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/版本与交付状态.md），不要仅凭本地源码版本判断线上功能。

## 本地开发

从仓库根目录按开发环境（https://github.com/XiongBoT/bme-ecg-system/blob/main/README.md#开发环境）创建 Python 环境，再进入 `心电云端平台/`：

```powershell
..\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-test.txt
..\.venv\Scripts\python.exe run_server.py --data-dir work/local-server
```

默认仅监听 `127.0.0.1:8766`。本地数据目录与正式服务器分开；当前账号、令牌及 HTTPS 配置见Linux 部署说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/deploy/linux/部署说明.txt）和公网访问说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/deploy/linux/手机公网访问说明.txt）。不要把历史无账号演示流程作为正式登录配置。

需要在本地启用现有模型时，在启动服务的同一 PowerShell 会话中执行：

```powershell
..\.venv\Scripts\python.exe -m pip install -r requirements-model.txt
$env:ECG_MODEL = 'cardioedge'
```

然后运行上面的启动命令。仅安装权重不会启用模型；`ECG_MODEL=none` 为不启用模型。模型与输入约束见云端模型说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/cloud_model/README.md）。

## 统一工作流程

登录后从记录页或“我的”打开**任务中心**。按上传中、等待/正在分析、需要处理、待分析、已有结果筛选；这里仅显示本人未删除的记录，每页 25 条。每项分别列出心搏分类与 QRS/RR 任务，可启动未运行任务或重试失败任务。“已有结果”也包括条件不足，不能据此判定正常；进入记录查看具体来源、版本、质量和结果。上传仍在进行时应回到采集终端继续或重试上传。

展开“上传后的自动分析”，分别勾选分类和 QRS/RR，点击保存。两个开关默认关闭，只作用于此后首次上传完成且归属于本人的记录，不补跑历史记录。关闭开关取消尚未入队的自动任务；已排队任务继续。队列满时约 30 秒后重试；模型未就绪、记录超过 100 万点等情况显示阻止原因，解决原因后可手动启动。网页关闭不影响已接受的后台任务。

记录详情新增**人工复核**：待复核、已查看、疑似干扰，以及最多 1000 字的备注。先阅读当前波形与两个分析状态，再保存。它表示人工查看情况，不修改原始数据或模型 N/S/V 标签，也不是诊断结论。同一结果被重跑、算法版本变化、备份恢复或另一个页面已经修改复核时，会提示重新查看；分析尚在排队/运行时不能确认“已查看”。需要更新时先刷新结果，再点击“刷新复核”（会舍弃尚未保存的表单文字）。

报告预览沿用当前波形窗口及已读取结果，增加复核标记、备注、保存时间；复核过期或与显示结果不同步会明确标注。用“打印 / 存储 PDF”保存，不会自动分享。打开的报告是当时的快照，需要最新内容时关闭并重新生成。

管理员从“我的”进入**运行总览**，集中查看设备连接、分析队列、未完成上传、磁盘空间、最近备份与问题处理入口。页面可见时每 15 秒刷新；网络失败保留上次内容并显示失败提示。提示规则：设备超过 35 秒无心跳显示离线（未上报显示未知）；未完成上传 15 分钟无更新；可用空间低于 1 GiB 或总容量 10%；最近 7 天的最新分析失败；没有成功备份或最近成功备份超过 7 天。问题是运行提示，不是医学告警，不发送外部推送。管理员仍不能查看其他用户的波形，备份仍只保存在服务器。

## 片段标注（本地完成，待部署）

在本人上传完成的记录中打开波形，展开“片段标注”：

1. 调整波形窗口，点击“使用当前窗口”，或填写相对记录起点的开始、结束秒数，范围最多 60 秒。
2. 选择“备注”“疑似干扰”或“需要关注”，填写最多 500 字说明并保存。标注是人工说明，不修改波形或分类结果。
3. 列表中点击“查看片段”定位回波形；“编辑”修改说明。“撤下”隐藏标注，勾选“显示已撤下”后可恢复。
4. 每页 25 条，每条记录最多 1000 条（包含已撤下）。多人或多个页面修改同一标注时会提示冲突，刷新核对后再保存，不会覆盖新版本。

未完成上传、回收站记录、其他用户记录不可标注。时间按 360 Hz 的采样编号定位；缺口仍保留，不会补造波形。每次修改在服务器留存版本记录，当前界面不提供逐版本历史查看。退出或切换账号会清空未保存表单。

## 每日自动备份（本地完成，待部署）

管理员打开“数据库管理 → 检查与备份 → 每日自动备份”，启用后选择每天的北京时间并保存。默认关闭，下一次执行时间、最近任务及错误均在页面显示。

计划和手动维护共用一个后台任务队列。忙碌时延后；服务停机多天只补做一次，恢复停机前排队的定时备份也算本次补做。剩余空间低于 1 GiB 或无法读取空间时暂停，15 分钟后重试；进入备份过程还会按归档大小检查余量，失败时明确显示原因。关闭计划不取消已经接受的备份任务。

备份只保存在服务器，第一版保留全部备份，不自动删除、下载或发往第三方。管理员应定期查看空间和任务结果。恢复备份到新目录后计划自动关闭，确认新环境和凭据后需重新启用。备份内容和恢复命令见服务器上的备份与恢复（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/使用说明.md#服务器上的备份与恢复）。

## 登录与找到记录

1. 从项目首页打开 HTTPS 网页，或启动 Windows/Android 客户端。
2. 使用本人账号登录；普通用户只查看归属于自己的记录。
3. 按设备和记录选择所需会话，核对采集时间、来源及上传状态。
4. 查看波形、历史位置与测量总结；按需要导出 CSV。

采集时间、云端登记时间和最后收块时间含义不同。刚上传的记录可能是历史转存；来源未知的记录不能当作新实采。记录仍在上传时，导出仅代表已经接收的部分。

新版导航（PR #59（https://github.com/XiongBoT/bme-ecg-system/pull/59） 已合并，待部署）：电脑左侧和手机底部统一提供“记录、设备、我的”，平板使用带文字的窄侧栏。宽屏电脑保留记录列表与结果同屏；平板与手机点选记录后进入结果，使用“返回记录”回到列表。切换设备或我的后返回，仍保留所选记录、筛选输入和页面位置。任务中心可从电脑侧栏、记录页或“我的”进入。

“我的”按我的工作台、偏好与帮助、账号与安全、管理工具分组；管理工具仅管理员可见。“应用设置”保留字体、对比度、刷新间隔等原有选项。导航借鉴 Grafana 常用入口优先（https://grafana.com/whats-new/2024-08-23-navigation-bookmarks/）、Home Assistant 个人设置分组（https://www.home-assistant.io/docs/configuration/user-configuration/）及 Android 大小屏导航模式（https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns），沿用本项目技术与视觉风格。旧 APK 需更新安装包才会取得新导航，刷新不能更新其内置页面。

## 手机使用流程

健康助手 1.1.0 延续“记录、设备、我的”底部导航。手机可选择授权且就绪的终端发起固定时长测量，实际采集在终端完成；无记录时按三步引导核对本人账号、设备端保存上传和手机刷新。

“今天、近七天”按设备记录的采集日期筛选，列表按上传登记时间由新到旧排列；“最近一条”打开当前筛选条件第一页的首条，不能据此认定它是最新采集的记录。列表和结果显示成功读取时间，刷新失败时标明保留的是上次数据。记录页顶部可以下拉刷新，也可使用刷新按钮。

点开记录后优先查看摘要、采集完整性和两项分析状态；“详细信息”展开采样点数与上传记录。终端心率统计、终端保存的分类与云端重新分析分别标明来源。设备页只展示当前账号获准访问的设备，管理员配置入口仍在“我的”。

“预览报告”包含当前已读取的摘要、分析来源和波形片段，明确注明片段范围、生成时间和设备时钟提示；完整数据通过 CSV 导出。安卓点击“打印 / 存储 PDF”打开系统打印窗口，浏览器版使用浏览器打印。报告不自动分享，换账号或换记录后预览失效。CSV 保存后可主动打开文件。

“我的”提供 APP 设置、版本与使用帮助；新版登录页可申请账号，等待管理员通过。忘记密码联系项目管理员重置。以上是当前源码行为，公网网页和已发布 APK 的版本状态分别见 手机端交付记录（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/手机端与安卓安装包.md）。

## 导出内容怎么选

| 需要什么 | 选择 | 内容与范围 |
| --- | --- | --- |
| 复核或另行处理原始数据 | 下载 CSV | 所选记录当前已接收的数据；上传未完成时不能当作完整测量 |
| 保存当前查看的摘要和波形 | 预览报告 → 打印／存储 PDF | 当前已读取的结果与波形窗口，注明来源、范围和时间；不是整条记录或诊断报告 |
| 管理员保护服务器数据 | 数据库管理 → 创建服务器备份 | 仅服务器保存数据库快照及引用的原始块，网页无下载；不含程序、模型、配置和派生分析缓存 |

CSV 保存后可主动打开文件；没有关联查看应用时，通过系统文件管理器查看保存位置。报告不自动分享，切换账号或记录后需重新预览。服务器恢复会撤销旧会话和设备凭据，须按下文恢复步骤处理。

## 分析与结果复核

当前模型为 CardioEdgeAI v1 INT8，使用 N/S/V 分类。仅已完成记录中满足来源、ADC、质量及上下文要求的有效实采片段进入分类；本地合成、板端模拟或未知模式可被拒绝。

在记录中启动分析后等待任务完成；查询已保存结果不会自动重新计算。通过心搏明细定位波形，结合拒绝原因和质量提示复核。模型分数不是诊断概率，N 类包含束支阻滞，S 类需特别复核。

分析结果与原始采样独立保存。模型或输入变化后是否需要重新分析，按界面状态判断；不要为重算删除原始数据。离线 HRV 研究报告与当前工作台功能是不同入口，见算法与评估（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/算法与评估.md）。

## 独立 QRS/RR 分析

当前源码另提供独立 QRS/RR 后台分析，不覆盖原始记录或分类结果。安装 `requirements-model.txt` 后即可使用，无需启用分类模型；记录上传完成后在“心搏与间期（QRS / RR）”卡片提交任务，退出页面不影响已接受的任务。

结果显示 R 峰数、平均 RR、换算心率、RR 变异性、有效时长/点数及排除原因。单记录上限 100 万采样点；模拟、模式不明或质量不足的输入可能没有可用结果。没有可信正常窦性间期标记时，HRV 显示不可用，不能用模型 N 类代替 NN。

是否部署须核对交付状态（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/版本与交付状态.md）；已发布旧 APK 不包含这些新页面。后台任务与结果版本、权限及升级回退边界见接口约定（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/接口约定.md#独立-qrsrr-分析2026-11-24待部署）。公开数据的离线评估与在线结果分别查阅算法与评估（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/算法与评估.md）。

## 统一管理后台

部署新版服务和网页后，管理员从“我的 → 管理工具 → 进入管理后台”进入 `/admin`。电脑显示分组侧栏，手机显示可换行的导航网格；“我的记录”与“任务中心”可随时返回日常工作。管理概览、运行总览、账号管理、采集设备、记录管理、检查与备份、操作记录使用同一导航，当前页或分区会高亮。管理概览侧重账号、设备与记录管理，运行总览侧重分析队列、磁盘及待处理问题。

管理分区跳转补充（任务 #61（https://github.com/XiongBoT/bme-ecg-system/issues/61），待审核部署）：已在数据库管理页面时，侧栏“记录管理、检查与备份、操作记录”只在页内定位，保留查询筛选和未保存的备份计划；从其他管理页面进入时仍正常打开对应分区。修改计划后仍需点击保存才会生效。

1. **查看总览。** 卡片显示在线设备、今日上传登记、待分配记录及最近分析失败；点击可进入对应筛选结果。今日按北京时间的云端登记日期统计，离线补传可能与采集日期不同。每条记录按分析类型取最近一次任务，重试成功后旧失败不再计入；回收站记录不计入总览。
2. **配置账号。** 在账号管理中搜索、筛选或创建普通账号，查看登录概况、关联设备和记录数量；点击“管理设备授权”进入该账号的设备列表。单项添加或取消只影响这个账号与这台设备，保留其他账号授权和既有记录。
3. **检查设备。** 按名称、编号、连接状态或账号授权情况查询并翻页，查看最近上报、最近上传和最近登记的记录。35 秒内收到心跳才显示近期在线；旧心跳显示“当前状态未知”，没有心跳显示“尚未上报”。已启用与近期在线是两种不同状态。
4. **处理例外。** 停用账号或设备不能新增授权，已有授权可保留或取消。旧版共享设备需在设备配置中勾选“确认改为单独授权”，再保存名单；只改名称不改变共享模式。多人同时改授权时，完整名单保存会核对打开时的名单，不一致则提示刷新且不保存本次修改。
5. **继续查看记录或维护。** 账号和设备详情可跳到记录元信息；日期、账号和设备筛选随链接保留，可清除筛选重新查询。历史无归属记录仍在账号页“分配历史记录”处理。管理员的管理入口不授予他人波形或分析结果读取权限。

总览显示读取时间，需点击刷新获取新状态。分析失败卡片提供排查入口，不在此执行重试；最后成功备份只表示创建时成功，恢复能力仍需单独校验。运行问题汇总现已由 `/operations` 提供，详见上方统一工作流程；全局账号审计与自动备份计划尚未包含在此源码基线。

Android 源码已将上述管理页面交给固定项目站点的系统浏览器，保留筛选条件；浏览器需独立登录，应用不传递登录凭据。入口是否可用取决于服务部署；已发布旧 APK 刷新不能获得新内置界面；发布状态见统一状态页（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/版本与交付状态.md）。

## 数据库管理

管理员登录后，在工作台账号区选择“数据库管理”（手机先进入“我的”）；电脑和手机使用同一个入口。普通账号继续查看自己的记录，不显示管理入口。服务部署需单独核对；已发布旧 APK 不包含本节新页面。

1. 查看记录数量、数据库体积及磁盘剩余空间，点击“统计占用”获取原始数据、分析缓存、备份和临时文件占用。文件占用标注最近统计时间，并非实时精确值；读取失败显示未知或统计不完整。
2. 按所属用户、采集设备、采集日期、状态和名称/编号查找记录，支持分页。管理员只查看元信息；波形仍按本人账号访问。
3. 完成上传和分析后可移入回收站，随后选择“回收站”筛选并恢复。回收站仍占磁盘空间；第一版不提供永久删除。
4. 点击“检查完整性”，后台核对数据库结构、外键、已登记原始块及点数。完成后查看问题数量和具体提示，不会自动删除或修复坏数据。检查通过不表示信号或诊断正确。
5. 点击“创建服务器备份”并确认。后台会生成数据库快照、核对该快照引用的原始块并校验归档；离开页面任务继续。仅显示备份状态、文件名、大小及摘要，网页不提供下载。

维护任务同一时间只执行一个，最近任务和操作记录保留在后台。任务失败/中断可在排除原因后重新创建；已完成备份列表表示创建当时成功，不保证后来没有被服务器人员移动或删除。备份和临时空间均计入占用，第一版不自动淘汰旧备份。

### 服务器上的备份与恢复

备份路径为实际 `ECG_DATA_DIR` 下的 `backups/ecg-backup-<任务编号>.zip`，权限限制为服务账号目录。管理员网页登录权限不授予该文件的下载权限；服务器运维人员应按原有服务器权限管理。

备份包含 `cloud.sqlite`、快照引用的原始波形块和 SHA256 清单，**不包含模型/QRS分析缓存、程序、模型文件或服务器配置**。它用于保护账号、归属和原始采集数据，不能代替部署前完整运行备份。

在服务器或隔离环境的模块根目录执行：

```sh
python tools/restore_database.py /实际数据目录/backups/ecg-backup-任务编号.zip --destination /实际恢复父目录/新目录
```

父目录须已存在，目标目录必须尚不存在；已有目标会拒绝，不覆盖线上数据。命令验证成功后才公布新目录，不自动切换服务。恢复后原浏览器会话和设备密钥全部失效，需重新登录、重新发放设备凭据；分析结果需重新计算。旧自动分析意图取消，活动测量请求失效，人工复核需重新确认，恢复不会启动旧采集命令。先以新目录启动隔离服务核对账号和记录，再单独安排正式切换。

任务异常终止后，下次维护进程启动只清理本模块标记且对应任务存在的已知临时文件。未知文件保留，显示在临时占用中，由服务器人员核实；不自动递归删除不明目录。ZIP公布后、任务状态提交前若断电，服务器可能保留未列入成功记录的归档，需在服务器验证后处理。

## 管理员账号管理

适用版本：主分支已包含 PR #29、#48 和 #47 的账号功能。推荐从 `/admin/accounts` 管理账号；下文“账号与待分配记录”为个人工作台保留的快捷窗口，待审核申请也在该窗口。旧 APK 和旧服务的入口可能不同；普通用户不能进入管理员管理窗口。

管理员登录后打开“账号与待分配记录”（手机先进入“我的”页），可按账号名称搜索，按可登录/已停用或角色筛选，每页显示 10 个账号。点击“刷新”更新概况；创建时间与最近成功登录缺少历史数据时显示“未记录”。“有效登录”是尚未过期的登录凭证数，不是实时在线人数。

- 展开“创建普通账号”，填写账号、初始密码及确认密码。账号以字母或数字开头，支持 3–32 位字母、数字、横线、下划线，大写会转为小写；密码须为 5–128 个字符。创建成功后通过可信渠道交付密码，并在设备管理中按需要授权采集设备。
- “重置密码”使该普通账号原有登录失效；“撤销登录”保留密码，要求已有登录重新验证，用户仍可用原密码再次登录。
- “停用”阻止账号登录并撤销原有登录，也使其不再成为设备可选接收人；“恢复”后可重新登录。已有记录、归属与设备授权仍保留。管理员账号本身不能在这里停用、重置或撤销登录。
- “分配历史记录”只列尚无归属的记录。明确选择使用者后确认，已归属记录不能在此改给别人。

操作成功后若刷新失败，成功提示仍保留；点击“刷新”核对最新状态，避免重复创建。关闭管理或密码窗口会清空密码输入。微信登录暂不实现。当前是源码功能，需另行更新云端及内置网页的 APK 后使用。

### 三种操作如何选择

| 操作 | 原密码还能登录吗 | 已有登录 | 记录、归属及设备授权 |
| --- | --- | --- | --- |
| 重置密码 | 否，改用新密码 | 全部撤销 | 保留 |
| 撤销登录 | 可以重新登录 | 全部撤销 | 保留 |
| 停用账号 | 停用期间不能登录；恢复后可用现有密码 | 全部撤销，恢复不会复活旧登录 | 保留；停用期间不列为设备可选接收人 |

如果要阻止账号继续登录，应选择“停用”；单独撤销登录不禁止再次登录。操作不取消已经获准执行中的业务请求。管理员不会因此获得该账号的波形读取权限。

## 健康助手、申请与测量

| 现象 | 检查与处理 |
| --- | --- |
| 没有申请账号、趋势或测量入口 | 核对服务 `/health` 的 `health_assistant_version=1`、页面版本与 APK 版本；旧包刷新不会更新内置资源 |
| 申请后不能登录 | 申请需管理员通过；重复账号可能已存在或正在审核。通过后使用申请时的密码；忘记密码请管理员重置 |
| 申请提示过于频繁 | 当前来源每小时最多 5 次，最多 200 条待审核；等待后重试或联系管理员，不反复提交 |
| 初始密码校验不一致 | 当前服务要求 5–128 字符；旧服务可能仍要求 10 字符。服务器命令行工具的旧提示仍写 10，实际验证见当前 `auth_store.py` |
| 没有可测量设备 | 核对设备授权、近 35 秒心跳、终端版本、真实串口模式和空闲状态；在线不等于远程就绪 |
| 测量请求过期 | 45 秒内未被终端领取会过期；核对终端后重新发起，不会晚些时候自动执行旧请求 |
| 手机关掉后仍在测量 | 计时在终端执行；需要提前结束时在终端停止，等待保存 |
| 上传失败或没有报告 | 先看终端保存与上传结果，再看分类/QRS 任务；本地记录保留，可补传。报告入口不代表两种分析都成功 |
| 趋势缺少记录或心率 | 仅本人完成且未回收的串口记录进入统计，按采集日期与页面 UTC 偏移分桶；缺失心率显示暂无，不补零 |
| 退出后账号密码仍会填入 | 主动勾选的记忆资料会保留；在 APP 设置清除，浏览器密码还需在浏览器密码管理器删除 |

## 任务中心与复核

- 没有入口：先核对版本与交付状态（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/版本与交付状态.md）。新增工作流程须部署新版服务；Android 使用内置页面时还需更新客户端，已有下载包不会自行获得全部新入口。
- 自动分析没启动：确认本人已保存对应开关，记录在启用后首次完成上传；旧记录、回收站记录、归属改变或账号停用不会自动补跑。队列繁忙会保留意图后重试；模型未配置或记录超限需先处理原因。原始上传不因自动分析失败回滚。
- 任务显示“条件不足”：查看来源和质量，合成、板端模拟及不足的有效片段不能产生可解释的实采结果。不要把条件不足当作正常。
- 复核提示不同步：先刷新波形和两项结果，再点击“刷新复核”；再次查看后保存。另一个页面已修改时会拒绝覆盖，避免丢失他人的新标记。原始记录和算法标签不受影响。
- 备份恢复后：旧自动意图取消、复核标记失效、分析缓存需重建；重新核对账号/设备权限后由本人提交分析。恢复不会自动启动备份里尚未执行的任务。
- 运行总览问题不消失：它展示当前规则匹配的状态，不是可以手动关闭的历史通知；按链接处理后刷新。磁盘数值是所在磁盘容量，不是心电文件占用。设备离线和分析失败均不表示医学异常。

## 连接、登录与分析

| 现象 | 检查顺序 |
| --- | --- |
| 网页或客户端无法连接 | 从首页核对当前 HTTPS 地址，检查网络及服务可用性；客户端连接问题不代表本地记录丢失 |
| 本地服务启动失败 | 从模块根目录运行，确认 Python 环境及 `requirements.txt`；检查端口是否占用、数据目录是否可写 |
| 账号登录失败 | 核对账号状态和平台地址；账号由管理员管理，服务器 SSH 密码不是平台登录密码 |
| 登录后没有记录 | 核对记录归属、账号、设备筛选及上传完成状态；未分配记录需管理员处理 |
| 模型显示 `not_configured` | 检查实际运行进程的 `ECG_MODEL`，模型依赖是否安装；本地与服务器的开关各自生效 |
| 健康检查 `model_result=null` | 健康检查不返回某条记录的结果；同时查看模型状态和目标会话的分析任务 |
| 模型拒绝或没有心搏结果 | 核对会话是否完整、输入来源、ADC、信号质量及上下文；模拟链路可验证上传，但不一定生成分类 |
| 手机看不到终端最新测量 | 先确认终端保存，再确认上传、设备授权和记录所属账号；终端总结不等于云端分析完成 |
| 旧脚本要求中转通道或找不到参考记录 | 这些属于历史联调工具；先看工具索引及归档说明，新克隆不包含原电脑的记录与凭据 |

## 统一管理后台排查

| 现象 | 检查顺序 |
| --- | --- |
| 没有管理后台或入口返回 404 | 核对服务与网页是否部署同一版本；旧 APK 需更新，新入口仅向管理员显示 |
| 显示设备已启用，但不在线 | 启用是配置状态；在线要求 35 秒内有心跳。先看最近上报时间，再查终端网络和设备凭据 |
| 今日登记数量与当天测量数量不同 | 总览按北京时间的云端登记日统计，补传不等于当天采集；通过卡片跳转会沿用同一日期口径 |
| 账号详情有设备，但无法添加授权 | 核对账号和设备是否启用；旧版共享设备需显式转换，不能通过单账号按钮静默改为独立名单 |
| 保存提示授权已被其他操作更新 | 本次修改未保存。刷新设备，核对最新名单再修改；仅改名不会覆盖授权 |
| 显示操作成功，同时提示读取失败 | 写入已成功，随后刷新失败。先刷新核实当前状态，不要仅凭读取错误重复变更 |
| 页面突然要求重新登录 | 其他页面退出、换号、撤销登录或权限变化会清除管理信息及凭据；返回个人工作台重新确认管理员账号 |
| 总览显示分析失败，但无重试按钮 | 本轮仅提供最近失败的管理摘要，分析仍由记录所属账号操作；管理员不能借此查看他人的波形 |

## 数据库管理排查

| 现象 | 检查顺序 |
| --- | --- |
| 看不到数据库管理入口 | 确认新版服务和网页已部署，并登录有效管理员账号；普通账号和设备凭据不具备后台管理权限 |
| 占用显示未统计或不完整 | 点击“统计占用”；核对扫描时间及目录读取权限，未知不能当成零；上传期间目录仍会增长 |
| 整理记录提示409 | 等待上传、排队或运行中的分析完成；维护任务409表示同一目录已有检查/扫描/备份任务 |
| 备份失败或显示空间不足 | 查看任务错误；需留出数据库快照、归档及至少256 MiB余量；第一版不会自动删除历史备份或原始数据 |
| 完整性检查发现问题 | 根据记录和块编号核对原始来源及服务器文件；不要通过删库或删记录掩盖问题，坏块不会自动修复 |
| 任务中断或一直运行 | 服务重启或管理页再次查询会启动恢复检查；中断后重新提交。未知临时文件保留，需服务器核实；无权限或损坏数据库应先修复运行环境 |
| 恢复提示目标已存在 | 选择不存在的新目录，保留原目录；恢复后需重新登录、重发设备凭据及重新分析，不会自动替换正式服务 |

## 记录与报告排查

| 现象 | 检查顺序 |
| --- | --- |
| 找不到刚测的记录 | 核对终端和手机的账号是否一致 → 确认已保存、上传 → 重置日期／设备／来源筛选 → 刷新；无归属记录由管理员处理 |
| 新 APK 界面与文档不同 | 先看安装版本；1.0.0 与 1.1.0 导航和功能不同，旧 APK 刷新不会替换内置页面，详见手机指南（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/手机端与安卓安装包.md） |
| “今天”没有记录，但最近上传能找到 | 快捷日期按设备记录的采集日期筛选，列表按上传登记时间排列；先取消日期筛选并核对设备时钟 |
| 显示上次数据或更新失败 | 当前保留的是以前成功读取的数据；联网后重试并核对读取时间，不把旧结果当成刚完成的分析 |
| 上传完成但分析没有结果 | 分别查看采集完整性、心搏分类和心搏与间期状态；分析条件不足或失败不等于正常 |
| 报告只有一小段波形 | 报告按当前波形窗口生成；调整窗口后重新预览，完整原始数据使用 CSV |
| CSV 保存后打不开 | 先在系统文件管理器确认保存位置；没有关联查看应用不代表保存失败 |
| 系统没有 PDF 保存选项 | 是否提供保存 PDF 由系统打印服务决定；手机端该流程仍需实机验收，完整原始数据可先用 CSV 保存 |

## 账号管理排查

以下针对已合并的新版源码，部署状态先查版本与交付状态（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/版本与交付状态.md）。详细操作见账号管理说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/使用说明.md#管理员账号管理）。

| 现象 | 检查与处理 |
| --- | --- |
| 找不到搜索、筛选或撤销登录 | 先核对是否为管理员，以及服务器是否已部署 PR #29；Android 还需更新内置页面的 APK。仓库已合并不等于当前页面已更新 |
| 创建时提示账号格式不正确或已存在 | 账号为 3–32 位字母、数字、横线、下划线，以字母或数字开头；首尾空白去除、大写转小写后仍须唯一。搜索现有账号再判断，勿反复提交 |
| 初始密码不能提交 | 检查密码是否为 5–128 个字符，两次输入是否一致；不要把真实密码写入反馈或截图 |
| 已提示创建成功，但列表未更新 | 点击“刷新”再搜索账号；刷新失败不代表创建失败，不要重复创建 |
| 新账号可以登录，却不在树莓派接收人列表中 | 在设备管理中核对该设备的用户授权，并确认账号已启用；创建账号不会自动授予所有设备采集权限 |
| 最近登录显示“未记录” | 旧系统没有保存历史时间，或账号尚无新版记录的成功登录；不代表该账号从未使用过。失败登录不会更新该时间 |
| 有效登录数与实际人数不同 | 该数统计尚未过期的登录凭证，不是在线人数或实体设备数；同一人可以有多个登录，关闭浏览器也不等于凭证立即失效 |
| 撤销后仍能再次登录 | 属于预期行为，原密码保留；若需阻止再次登录，应停用账号。若密码不应继续使用，重置密码后再核对状态 |
| 恢复账号后旧窗口仍提示登录失效 | 恢复不会复活已撤销的登录，使用当前密码重新登录 |
| 列表加载失败或登录校验失效 | 先刷新或重新登录，再核对账号/目标和当前状态；确认操作结果前不要反复重置密码或分配记录 |

## 片段标注与自动备份排查（本地增量）

| 现象 | 检查与处理 |
| --- | --- |
| 看不到标注或每日备份 | 本轮尚未部署；核对服务端及网页版本，旧 APK 需要更新内置资源 |
| 标注无法保存 | 等待上传完成，核对所属账号、首尾时间、60秒范围和500字限制；采样缺口不会自动填补 |
| 标注或计划提示已被修改 | 当前写入未保存，先刷新并核对其他页面的修改，再重新操作 |
| 撤下的标注不见了 | 勾选“显示已撤下”，找到条目后恢复；记录回收时需先恢复记录 |
| 计划已启用但没有备份 | 核对北京时间的下一次执行、维护队列、空间及最近任务；空间阻止后15分钟重试，归档失败可手动重试 |
| 关闭计划后仍在备份 | 已接受任务继续，关闭只阻止后续定时提交 |
| 恢复后不再定时备份 | 预期行为；确认新目录、环境及重新发放的凭据后，由管理员重新启用 |

## 验证工具的边界

`verify_live_capture.py --offline` 只检查本地证据，不证明线上验收通过。`verify_live_model.py` 读取已有云端结果并在本地复算；`verify_cloud_model.py` 会请求云端分析。运行前查看工具分类（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/tools/README.md），不要把所有 `verify_` 脚本当作无副作用单元测试。

## 报告问题

提供提交编号、入口、操作步骤、错误消息以及是否本地/模拟/实体环境。使用脱敏的合成示例复现；不要上传账号数据库、访问令牌、真实记录或私钥。正式服务的升级和回退按部署说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/deploy/README.md）执行。
