# 云端快速开始

云端导航（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/README.md） · 使用说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/使用说明.md） · 故障排查（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/故障排查.md）

## 使用现有平台

1. 从项目首页（https://github.com/XiongBoT/bme-ecg-system/blob/main/README.md#应用下载）选择网页、Windows 或 Android 下载；iPhone 使用网页，可添加到主屏幕。
2. 使用自己的心电平台账号登录。没有账号或忘记密码时联系项目管理员，不需要申请 GitHub 仓库写入权限。
3. 在树莓派终端选择同一个使用者，测量后保存并上传；手机本身不负责采集。
4. 回到工作台刷新，选择记录，核对来源、采集完整性和上传状态，再查看摘要、波形及分析。需要完整数据时导出 CSV。

没有找到记录时，按排查顺序（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/故障排查.md#记录与报告排查）核对账号、上传和筛选；管理员分配账号、设备及历史记录见使用说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/使用说明.md#管理员账号管理待部署）。

### 先确认使用的是哪个版本

当前公开下载是 Android 1.0.0 试用版，其导航为“记录、结果、账号”。新源码 1.0.2 使用“记录、设备、我的”，并包含引导和报告预览；数据库管理、账号管理优化及独立 QRS/RR 也已合并，但仍须部署服务端和更新 APK 才能在用户端使用。各端状态统一见版本与交付状态（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/版本与交付状态.md），不要仅凭本地源码版本判断线上功能。

## 本地开发

从仓库根目录按开发环境（https://github.com/XiongBoT/bme-ecg-system/blob/main/README.md#开发环境）创建 Python 环境，再进入 `心电云端平台/`：

```powershell
..\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-test.txt
..\.venv\Scripts\python.exe run_server.py --data-dir work/local-server
```

默认仅监听 `127.0.0.1:8766`。本地数据目录与正式服务器分开；当前账号、令牌及 HTTPS 配置见Linux 部署说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/deploy/linux/部署说明.txt）和公网访问说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/deploy/linux/手机公网访问说明.txt）。不要把历史无账号演示流程作为正式登录配置。

需要在本地启用现有模型时，在启动服务的同一 PowerShell 会话中执行：

```powershell
..\.venv\Scripts\python.exe -m pip install -r requirements-model.txt
$env:ECG_MODEL = 'cardioedge'
```

然后运行上面的启动命令。仅安装权重不会启用模型；`ECG_MODEL=none` 为不启用模型。模型与输入约束见云端模型说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/cloud_model/README.md）。

## 登录与找到记录

1. 从项目首页打开 HTTPS 网页，或启动 Windows/Android 客户端。
2. 使用本人账号登录；普通用户只查看归属于自己的记录。
3. 按设备和记录选择所需会话，核对采集时间、来源及上传状态。
4. 查看波形、历史位置与测量总结；按需要导出 CSV。

采集时间、云端登记时间和最后收块时间含义不同。刚上传的记录可能是历史转存；来源未知的记录不能当作新实采。记录仍在上传时，导出仅代表已经接收的部分。

## 手机使用流程（1.0.2 源码，待发布）

手机底部为“记录、设备、我的”。测量在采集终端完成，手机查看已上传记录；无记录时按三步引导核对本人账号、设备端保存上传和手机刷新。

“今天、近七天”按设备记录的采集日期筛选，列表按上传登记时间由新到旧排列；“最近一条”打开当前筛选条件第一页的首条，不能据此认定它是最新采集的记录。列表和结果显示成功读取时间，刷新失败时标明保留的是上次数据。记录页顶部可以下拉刷新，也可使用刷新按钮。

点开记录后优先查看摘要、采集完整性和两项分析状态；“详细信息”展开采样点数与上传记录。终端心率统计、终端保存的分类与云端重新分析分别标明来源。设备页只展示当前账号获准访问的设备，管理员配置入口仍在“我的”。

“预览报告”包含当前已读取的摘要、分析来源和波形片段，明确注明片段范围、生成时间和设备时钟提示；完整数据通过 CSV 导出。安卓点击“打印 / 存储 PDF”打开系统打印窗口，浏览器版使用浏览器打印。报告不自动分享，换账号或换记录后预览失效。CSV 保存后可主动打开文件。

“我的”提供版本与使用帮助；没有账号或忘记密码时联系为你创建账号的项目管理员。以上是当前源码行为，公网网页和已发布 APK 的版本状态分别见 手机端交付记录（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/手机端与安卓安装包.md）。

## 导出内容怎么选

| 需要什么 | 选择 | 内容与范围 |
| --- | --- | --- |
| 复核或另行处理原始数据 | 下载 CSV | 所选记录当前已接收的数据；上传未完成时不能当作完整测量 |
| 保存当前查看的摘要和波形 | 预览报告 → 打印／存储 PDF | 当前已读取的结果与波形窗口，注明来源、范围和时间；不是整条记录或诊断报告 |
| 管理员保护服务器数据 | 数据库管理 → 创建服务器备份 | 仅服务器保存数据库快照及引用的原始块，网页无下载；不含程序、模型、配置和派生分析缓存 |

CSV 保存后可主动打开文件；没有关联查看应用时，通过系统文件管理器查看保存位置。报告不自动分享，切换账号或记录后需重新预览。服务器恢复会撤销旧会话和设备凭据，须按下文恢复步骤处理。

## 分析与结果复核

当前模型为 CardioEdgeAI v1 INT8，使用 N/S/V 分类。仅已完成记录中满足来源、ADC、质量及上下文要求的有效实采片段进入分类；本地合成、板端模拟或未知模式可被拒绝。

在记录中启动分析后等待任务完成；查询已保存结果不会自动重新计算。通过心搏明细定位波形，结合拒绝原因和质量提示复核。模型分数不是诊断概率，N 类包含束支阻滞，S 类需特别复核。

分析结果与原始采样独立保存。模型或输入变化后是否需要重新分析，按界面状态判断；不要为重算删除原始数据。离线 HRV 研究报告与当前工作台功能是不同入口，见算法与评估（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/算法与评估.md）。

## 独立 QRS/RR 分析（待部署）

当前源码另提供独立 QRS/RR 后台分析，不覆盖原始记录或分类结果。安装 `requirements-model.txt` 后即可使用，无需启用分类模型；记录上传完成后在“心搏与间期（QRS / RR）”卡片提交任务，退出页面不影响已接受的任务。

结果显示 R 峰数、平均 RR、换算心率、RR 变异性、有效时长/点数及排除原因。单记录上限 100 万采样点；模拟、模式不明或质量不足的输入可能没有可用结果。没有可信正常窦性间期标记时，HRV 显示不可用，不能用模型 N 类代替 NN。

本轮源码尚未部署公网，也未更新已发布 APK。后台任务与结果版本、权限及升级回退边界见接口约定（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/接口约定.md#独立-qrsrr-分析2026-11-24待部署）。公开数据的离线评估与在线结果分别查阅算法与评估（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/算法与评估.md）。

## 设备和账号

管理员在设备管理中维护设备、授权用户及凭据；普通用户按分配权限访问。树莓派客户端需要匹配的云端地址、设备授权和记录归属。既有未分配记录由管理员处理。

## 数据库管理（源码已实现，待部署）

管理员登录后，在工作台账号区选择“数据库管理”（手机先进入“我的”）；电脑和手机使用同一个入口。普通账号继续查看自己的记录，不显示管理入口。当前公网和已发布安装包尚未更新本功能。

1. 查看记录数量、数据库体积及磁盘剩余空间，点击“统计占用”获取原始数据、分析缓存、备份和临时文件占用。文件占用标注最近统计时间，并非实时精确值；读取失败显示未知或统计不完整。
2. 按所属用户、采集设备、采集日期、状态和名称/编号查找记录，支持分页。管理员只查看元信息；波形仍按本人账号访问。
3. 完成上传和分析后可移入回收站，随后选择“回收站”筛选并恢复。回收站仍占磁盘空间；第一版不提供永久删除。
4. 点击“检查完整性”，后台核对数据库结构、外键、已登记原始块及点数。完成后查看问题数量和具体提示，不会自动删除或修复坏数据。检查通过不表示信号或诊断正确。
5. 点击“创建服务器备份”并确认。后台会生成数据库快照、核对该快照引用的原始块并校验归档；离开页面任务继续。仅显示备份状态、文件名、大小及摘要，网页不提供下载。

维护任务同一时间只执行一个，最近任务和操作记录保留在后台。任务失败/中断可在排除原因后重新创建；已完成备份列表表示创建当时成功，不保证后来没有被服务器人员移动或删除。备份和临时空间均计入占用，第一版不自动淘汰旧备份。

### 服务器上的备份与恢复

备份路径为实际 `ECG_DATA_DIR` 下的 `backups/ecg-backup-<任务编号>.zip`，权限限制为服务账号目录。管理员网页登录权限不授予该文件的下载权限；服务器运维人员应按原有服务器权限管理。

备份包含 `cloud.sqlite`、快照引用的原始波形块和 SHA256 清单，**不包含模型/QRS分析缓存、程序、模型文件或服务器配置**。它用于保护账号、归属和原始采集数据，不能代替部署前完整运行备份。

在服务器或隔离环境的模块根目录执行：

```sh
python tools/restore_database.py /实际数据目录/backups/ecg-backup-任务编号.zip --destination /实际恢复父目录/新目录
```

父目录须已存在，目标目录必须尚不存在；已有目标会拒绝，不覆盖线上数据。命令验证成功后才公布新目录，不自动切换服务。恢复后原浏览器会话和设备密钥全部失效，需重新登录、重新发放设备凭据；分析结果需重新计算。先以新目录启动隔离服务核对账号和记录，再单独安排正式切换。

任务异常终止后，下次维护进程启动只清理本模块标记且对应任务存在的已知临时文件。未知文件保留，显示在临时占用中，由服务器人员核实；不自动递归删除不明目录。ZIP公布后、任务状态提交前若断电，服务器可能保留未列入成功记录的归档，需在服务器验证后处理。

## 管理员账号管理（待部署）

适用版本：PR #29 已合并的源码。当前公网及 Android 1.0.0 试用包尚未更新本节界面；普通用户不能进入管理员管理窗口。

管理员登录后打开“账号与待分配记录”（手机先进入“我的”页），可按账号名称搜索，按可登录/已停用或角色筛选，每页显示 10 个账号。点击“刷新”更新概况；创建时间与最近成功登录缺少历史数据时显示“未记录”。“有效登录”是尚未过期的登录凭证数，不是实时在线人数。

- 展开“创建普通账号”，填写账号、初始密码及确认密码。账号以字母或数字开头，支持 3–32 位字母、数字、横线、下划线，大写会转为小写；密码须为 5–128 个字符。创建成功后通过可信渠道交付密码，并在设备管理中按需要授权采集设备。
- “重置密码”使该普通账号原有登录失效；“撤销登录”保留密码，要求已有登录重新验证，用户仍可用原密码再次登录。
- “停用”阻止账号登录并撤销原有登录，也使其不再成为设备可选接收人；“恢复”后可重新登录。已有记录、归属与设备授权仍保留。管理员账号本身不能在这里停用、重置或撤销登录。
- “分配历史记录”只列尚无归属的记录。明确选择使用者后确认，已归属记录不能在此改给别人。

操作成功后若刷新失败，成功提示仍保留；点击“刷新”核对最新状态，避免重复创建。关闭管理或密码窗口会清空密码输入。微信登录暂不实现。当前是源码功能，需另行更新云端及内置网页的 APK 后使用。

### 三种操作如何选择

| 操作 | 原密码还能登录吗 | 已有登录 | 记录、归属及设备授权 |
| --- | --- | --- | --- |
| 重置密码 | 否，改用新密码 | 全部撤销 | 保留 |
| 撤销登录 | 可以重新登录 | 全部撤销 | 保留 |
| 停用账号 | 停用期间不能登录；恢复后可用现有密码 | 全部撤销，恢复不会复活旧登录 | 保留；停用期间不列为设备可选接收人 |

如果要阻止账号继续登录，应选择“停用”；单独撤销登录不禁止再次登录。操作不取消已经获准执行中的业务请求。管理员不会因此获得该账号的波形读取权限。

### 新功能如何更新到各端

| 入口 | 更新方式 |
| --- | --- |
| 手机/电脑浏览器、PWA、Windows 网页入口 | 服务器部署新版后重新打开或刷新页面；Windows 启动器自身版本与网页功能分别维护 |
| Android 内置网页应用 | 服务器更新后，还需构建并发布包含新版页面的 APK，沿用原签名并提高版本号；仅刷新 APK 不会替换内置页面 |

部署与安装包发布另行安排，操作前核对备份及回退方案。原始记录和正式账号不通过重新建库来更新。常见问题见账号管理排查（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/故障排查.md#账号管理排查）。

# 云端故障排查

快速开始（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/快速开始.md） · 使用说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/使用说明.md） · 辅助工具（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/tools/README.md）

先区分“当前版本没有这个功能”和“已有功能运行失败”。核对交付状态（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/版本与交付状态.md），再选择下方现象；不要用重新建库或删除记录来解决版本差异。

## 连接、登录与分析

| 现象 | 检查顺序 |
| --- | --- |
| 网页或客户端无法连接 | 从首页核对当前 HTTPS 地址，检查网络及服务可用性；客户端连接问题不代表本地记录丢失 |
| 本地服务启动失败 | 从模块根目录运行，确认 Python 环境及 `requirements.txt`；检查端口是否占用、数据目录是否可写 |
| 账号登录失败 | 核对账号状态和平台地址；账号由管理员管理，服务器 SSH 密码不是平台登录密码 |
| 登录后没有记录 | 核对记录归属、账号、设备筛选及上传完成状态；未分配记录需管理员处理 |
| 模型显示 `not_configured` | 检查实际运行进程的 `ECG_MODEL`，模型依赖是否安装；本地与服务器的开关各自生效 |
| 健康检查 `model_result=null` | 健康检查不返回某条记录的结果；同时查看模型状态和目标会话的分析任务 |
| 模型拒绝或没有心搏结果 | 核对会话是否完整、输入来源、ADC、信号质量及上下文；模拟链路可验证上传，但不一定生成分类 |
| 手机看不到终端最新测量 | 先确认终端保存，再确认上传、设备授权和记录所属账号；终端总结不等于云端分析完成 |
| 旧脚本要求中转通道或找不到参考记录 | 这些属于历史联调工具；先看工具索引及归档说明，新克隆不包含原电脑的记录与凭据 |

## 数据库管理排查

| 现象 | 检查顺序 |
| --- | --- |
| 看不到数据库管理入口 | 确认新版服务和网页已部署，并登录有效管理员账号；普通账号和设备凭据不具备后台管理权限 |
| 占用显示未统计或不完整 | 点击“统计占用”；核对扫描时间及目录读取权限，未知不能当成零；上传期间目录仍会增长 |
| 整理记录提示409 | 等待上传、排队或运行中的分析完成；维护任务409表示同一目录已有检查/扫描/备份任务 |
| 备份失败或显示空间不足 | 查看任务错误；需留出数据库快照、归档及至少256 MiB余量；第一版不会自动删除历史备份或原始数据 |
| 完整性检查发现问题 | 根据记录和块编号核对原始来源及服务器文件；不要通过删库或删记录掩盖问题，坏块不会自动修复 |
| 任务中断或一直运行 | 服务重启或管理页再次查询会启动恢复检查；中断后重新提交。未知临时文件保留，需服务器核实；无权限或损坏数据库应先修复运行环境 |
| 恢复提示目标已存在 | 选择不存在的新目录，保留原目录；恢复后需重新登录、重发设备凭据及重新分析，不会自动替换正式服务 |

## 记录与报告排查

| 现象 | 检查顺序 |
| --- | --- |
| 找不到刚测的记录 | 核对终端和手机的账号是否一致 → 确认已保存、上传 → 重置日期／设备／来源筛选 → 刷新；无归属记录由管理员处理 |
| 新 APK 界面与文档不同 | 先看安装版本；1.0.0 与 1.0.2 导航不同，旧 APK 刷新不会替换内置页面，详见手机指南（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/手机端与安卓安装包.md） |
| “今天”没有记录，但最近上传能找到 | 快捷日期按设备记录的采集日期筛选，列表按上传登记时间排列；先取消日期筛选并核对设备时钟 |
| 显示上次数据或更新失败 | 当前保留的是以前成功读取的数据；联网后重试并核对读取时间，不把旧结果当成刚完成的分析 |
| 上传完成但分析没有结果 | 分别查看采集完整性、心搏分类和心搏与间期状态；分析条件不足或失败不等于正常 |
| 报告只有一小段波形 | 报告按当前波形窗口生成；调整窗口后重新预览，完整原始数据使用 CSV |
| CSV 保存后打不开 | 先在系统文件管理器确认保存位置；没有关联查看应用不代表保存失败 |
| 系统没有 PDF 保存选项 | 是否提供保存 PDF 由系统打印服务决定；手机端该流程仍需实机验收，完整原始数据可先用 CSV 保存 |

## 账号管理排查

以下针对已合并的新版源码，部署状态先查版本与交付状态（https://github.com/XiongBoT/bme-ecg-system/blob/main/docs/版本与交付状态.md）。详细操作见账号管理说明（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/docs/使用说明.md#管理员账号管理待部署）。

| 现象 | 检查与处理 |
| --- | --- |
| 找不到搜索、筛选或撤销登录 | 先核对是否为管理员，以及服务器是否已部署 PR #29；Android 还需更新内置页面的 APK。仓库已合并不等于当前页面已更新 |
| 创建时提示账号格式不正确或已存在 | 账号为 3–32 位字母、数字、横线、下划线，以字母或数字开头；首尾空白去除、大写转小写后仍须唯一。搜索现有账号再判断，勿反复提交 |
| 初始密码不能提交 | 检查密码是否为 5–128 个字符，两次输入是否一致；不要把真实密码写入反馈或截图 |
| 已提示创建成功，但列表未更新 | 点击“刷新”再搜索账号；刷新失败不代表创建失败，不要重复创建 |
| 新账号可以登录，却不在树莓派接收人列表中 | 在设备管理中核对该设备的用户授权，并确认账号已启用；创建账号不会自动授予所有设备采集权限 |
| 最近登录显示“未记录” | 旧系统没有保存历史时间，或账号尚无新版记录的成功登录；不代表该账号从未使用过。失败登录不会更新该时间 |
| 有效登录数与实际人数不同 | 该数统计尚未过期的登录凭证，不是在线人数或实体设备数；同一人可以有多个登录，关闭浏览器也不等于凭证立即失效 |
| 撤销后仍能再次登录 | 属于预期行为，原密码保留；若需阻止再次登录，应停用账号。若密码不应继续使用，重置密码后再核对状态 |
| 恢复账号后旧窗口仍提示登录失效 | 恢复不会复活已撤销的登录，使用当前密码重新登录 |
| 列表加载失败或登录校验失效 | 先刷新或重新登录，再核对账号/目标和当前状态；确认操作结果前不要反复重置密码或分配记录 |

## 验证工具的边界

`verify_live_capture.py --offline` 只检查本地证据，不证明线上验收通过。`verify_live_model.py` 读取已有云端结果并在本地复算；`verify_cloud_model.py` 会请求云端分析。运行前查看工具分类（https://github.com/XiongBoT/bme-ecg-system/blob/main/心电云端平台/tools/README.md），不要把所有 `verify_` 脚本当作无副作用单元测试。
