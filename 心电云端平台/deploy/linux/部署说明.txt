普通云主机部署：腾讯云/阿里云 Ubuntu 24.04
适用范围：下文保留早期“本机监听 + SSH 隧道”的首次安装流程，不是当前公网服务状态。
2026-11-23 已有基础 HTTPS 部署记录；当前源码、公开下载和部署验证分别见根 docs/版本与交付状态.md。
当前升级顺序、账号初始化和回退入口：心电云端平台/docs/部署与升级.md。
新建公网服务须同时按本目录“手机公网访问说明.txt”启用账号认证与 HTTPS；不要把无账号隧道演示直接暴露到公网。

配置与目录
普通CPU，建议2核2GB、40GB系统盘即可开始课程联调。
默认模型空置；本包另含可显式启用的CardioEdgeAI v1 INT8，启用方法见文末。
使用Ubuntu 24.04系统镜像和普通SSH登录用户，不在root目录安装。
代码：~/ecg-cloud；独立Python环境：~/ecg-cloud/.venv。
数据：~/ecg-cloud-data，独立于代码包；不清空、不放入部署压缩包。
服务：云主机127.0.0.1:8766，仅通过SSH加密通道访问。
部署包没有本地采集数据、数据库、密码、密钥或日志；含固定模型权重及其许可证。
SQLite保留当前默认回滚日志模式，使用单个Uvicorn进程。

首次安装（在云主机普通用户SSH终端运行）
1. 若尚未安装系统组件，由用户执行：
   sudo apt-get update
   sudo apt-get install -y python3-venv unzip
2. 将ecg-cloud-linux.zip传到该用户主目录。
   例如电脑PowerShell运行以下命令，并把用户和地址改成已购买实例的真实值：
   scp "ecg-cloud-linux.zip" 用户@云主机地址:~/
3. 确认~/ecg-cloud目录尚不存在，再解压。若已存在，先核对已有部署，勿覆盖或删除数据：
   test ! -e "$HOME/ecg-cloud" && unzip -n "$HOME/ecg-cloud-linux.zip" -d "$HOME"
4. 在云主机运行：
   bash ~/ecg-cloud/deploy/linux/install.sh
   安装脚本校验文件清单、创建独立环境、安装固定版本依赖，并放置用户服务文件。
   安装脚本不使用sudo、不改全局Python、不生成认证密钥、不改防火墙。
5. 启动：
   systemctl --user enable --now ecg-cloud.service
   systemctl --user status ecg-cloud.service --no-pager
6. 验证：
   curl --fail http://127.0.0.1:8766/health
   正常返回ok=true、model_status=not_configured、model_result=null。

退出SSH后保持运行（可选）
用户服务默认依赖该用户的登录会话。若需退出SSH后及开机时继续运行，可执行：
   sudo loginctl enable-linger "$(id -un)"
这会启用当前用户的后台服务管理器，影响该用户的其他用户服务，不是只针对本项目。
安装脚本不会自动执行该系统设置，也不会为其他用户启用。
查看状态：loginctl show-user "$(id -un)" -p Linger
若以后要关闭，先确认该用户没有其他服务依赖linger，再手动disable-linger。

没有用户服务管理器时的前台备用
   bash ~/ecg-cloud/deploy/linux/start.sh
保持该SSH窗口打开；Ctrl+C会停止服务。不能把此方式描述为退出终端后持续运行。

电脑查看云端网页
云端服务使用8766端口，电脑本地使用8767，避免与现有本机Demo的8766冲突。
在电脑PowerShell中运行，并保持窗口打开：
   ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=3 -L 127.0.0.1:8767:127.0.0.1:8766 用户@云主机地址
浏览器打开 http://127.0.0.1:8767/ 。
该网页的HTTP连接经过SSH到云主机，计算和存储实际位于云端。
该地址只供建立隧道的电脑访问，不是可转发给老师的公共网址。
首次SSH连接应对照云控制台核对主机指纹；不要关闭主机密钥校验。

树莓派上传
树莓派与电脑分别连接同一云主机。树莓派另开终端保持隧道：
   ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=3 -L 127.0.0.1:18766:127.0.0.1:8766 用户@云主机地址
将包中的uploader.py和protocol.py放到树莓派一个独立目录（不要覆盖终端自带的protocol.py），运行：
   python3 uploader.py --session-dir "已有会话完整目录" --url http://127.0.0.1:18766 --watch
上传器只读已提交记录；Ctrl+C停止上传，不停止其他进程中的采集。
上传器会与云端清单重新核对，重复块不增加点数，网络失败后保留原始数据。
上面无凭据 uploader 命令仅适用于隔离的旧演示服务。当前账号模式使用终端自身 cloud/ 上传链路和独立设备凭据，配置见树莓派心电终端/docs/云端账号与记录归属.txt。终端与云端均已实现分类，是否启用及验证须核对所用版本。

运行和停用
日志：journalctl --user -u ecg-cloud.service -n 100 --no-pager
停止：systemctl --user disable --now ecg-cloud.service
停止服务不会删除~/ecg-cloud-data。
备份时先停服务，将~/ecg-cloud-data整目录复制或打包，再重新启动，避免SQLite和块文件不一致。
演示结束后，先备份并核对CSV、原始数据及代码，再按云服务商界面停用/释放付费资源。
停程序、停机器和停止云资源计费不是同一件事；本脚本不购买、释放或续费资源。

每次新部署均需执行的验收
上传一段明确来源的数据；观察网页点数增长与波形；结束会话并核对清单与CSV。
重启用户服务后确认旧记录仍可读取；模型状态须与本次配置一致：未启用为 not_configured，启用后另查依赖和 ready 状态。
本地包检查不能替代上述云端运行验证。

可选：显式启用现有三分类模型
模型代码和权重来自已验证的树莓派终端CardioEdgeAI v1 INT8，记录于cloud_model/SOURCE.json。
权重SHA256：1398ea833ff65c90d63ed3174722c9280fa6606ab2c165bfa7c53ca8fe264a41。
仅依赖NumPy、SciPy，无需PyTorch或GPU；不对本地合成、板端模拟、未知模式或无效ADC分类。
先安装可选依赖：
   ~/ecg-cloud/.venv/bin/python -m pip install -r ~/ecg-cloud/requirements-model.txt
在用户服务drop-in中设置环境变量ECG_MODEL=cardioedge，再重启服务：
   systemctl --user edit ecg-cloud.service
写入：
   [Service]
   Environment=ECG_MODEL=cardioedge
保存后运行：
   systemctl --user daemon-reload
   systemctl --user restart ecg-cloud.service
前台备用可运行：
   ECG_MODEL=cardioedge bash ~/ecg-cloud/deploy/linux/start.sh
启用成功时/health的model_status为ready；未安装依赖/权重不匹配时为error，不假装已就绪。
GET /api/sessions/会话编号/analysis只读状态或已保存结果；POST同地址对已完成会话按需复算。
分析结果独立保存在~/ecg-cloud-data/analysis，原始数据不修改。
上面的同步 POST 保留兼容行为；当前页面主要使用 POST /api/sessions/{id}/analysis-jobs 和 physiology-jobs 提交持久任务（202），两类分析共用一个计算进程，最多 64 项活动任务，队列满返回 429。不要用旧同步接口的 409 说明推断新队列行为，详见根 docs/接口约定.md。
模型默认仍可关闭（不设置ECG_MODEL或设为none）；关闭后model_result保持null。
N类包含束支阻滞，S类能力有限，模型分数不是诊断概率，结果用于课程研究演示。
