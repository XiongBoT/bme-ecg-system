# 云端协作者上手

[云端文档](README.md) · [团队协作](../../docs/团队协作.md) · [部署与升级](部署与升级.md) · [版本与交付状态](../../docs/版本与交付状态.md)

本页面向共同开发和维护项目服务器的成员。先确认身份和目标实例，再做只读检查；升级、重启或回退按对应任务的授权执行。本文提供操作流程，不作为协作者实际登录成功或生产升级完成的证据。

## 先分清四种账号

| 身份 | 用途 | 从哪里取得权限 |
| --- | --- | --- |
| GitHub 账号 | 克隆代码、提交分支和 PR | 接受仓库协作邀请；流程见[贡献指南](../../CONTRIBUTING.md) |
| 腾讯云协作者身份 | 访问项目轻量应用服务器及获准的控制台操作 | 主账号所有者将本人腾讯云账号添加为协作者，并关联项目策略 |
| Linux 用户 | 在服务器终端中查看服务、日志或执行获准维护 | 由服务器维护人员说明登录方式和服务运行用户 |
| 心电平台账号 | 在网页查看本人记录；平台管理员管理账号、设备和备份 | 平台申请或管理员创建，见[管理员指南](../../docs/管理员指南.md) |

这四种身份的授权分别维护。仓库写权限不自动授予服务器登录，腾讯云控制台权限也不自动授予心电平台管理员角色。个人云账号、密码、验证码、私钥和平台凭据通过各自的登录或交付流程使用，不写进仓库或公开 Issue。

开始前请维护人员私下确认：项目所属腾讯云主账号、本人协作者身份、授权范围、目标地域及实例、Linux 服务运行用户，以及最近的部署记录和回退资料。成员名单和当前授权以 GitHub/CAM 实际设置为准，本页不保存个人账号清单。

## 登录项目服务器

1. 打开[腾讯云登录页](https://cloud.tencent.com/login)，使用自己的腾讯云账号登录。
2. 有多个身份时，选择项目主账号下的**协作者身份**；只进入自己的主账号可能看到空的资源列表。协作者使用自己的登录凭据，无需共享项目主账号密码，见[腾讯云协作者登录说明](https://cloud.tencent.com/document/product/598/36621)。如果要求多因素验证，按本人账号的验证流程完成；首次绑定规则见[官方 MFA 说明](https://cloud.tencent.com/document/product/598/36626)。
3. 打开[轻量应用服务器控制台](https://console.cloud.tencent.com/lighthouse/instance/index)，选择**北京（ap-beijing）**，查找项目实例 **ecg-course-demo**。这来自项目既有部署记录；若实例迁移或改名，以维护人员确认的新记录为准，不尝试维护名称相近的其他实例。
4. 核对所属账号、地域和实例后，点击该实例的“登录”。按维护人员提供的方式进入 Linux，并确认当前用户。首次只查看状态，不因页面报错重复创建实例、重置密码或重装系统。

项目协作策略使用 `ECGCourseDemoCollaborator` 这一名称。维护人员应在 CAM 核对它是否关联到目标协作者及其实际内容；策略名称相同不代表权限内容永远相同。实例列表查询可能允许跨地域读取元信息，终端登录和命令操作仍须核对目标实例授权。

控制台终端除 Lighthouse 外，还可能依赖 OrcaTerm 与 TAT 授权，详见[腾讯云指定资源授权说明](https://cloud.tencent.com/document/product/1207/107493)。出现拒绝时按具体操作和资源检查，不通过授予全账号管理员权限来代替定位。

## 首次只读检查

现有 Linux 部署脚本采用用户级服务 `ecg-cloud.service`，默认程序目录为 `~/ecg-cloud`，数据目录为 `~/ecg-cloud-data`。这里的 `~` 是**服务运行用户的主目录**；实际路径和用户以部署记录为准，不能把刚登录的 root 主目录当成服务目录。布局依据见[Linux 部署说明](../deploy/linux/部署说明.txt)和[启动脚本](../deploy/linux/start.sh)。

先执行 `whoami` 和 `pwd`。确认已进入服务运行用户的会话后，再运行以下只读检查：

```sh
whoami
pwd
systemctl --user status ecg-cloud.service --no-pager
journalctl --user -u ecg-cloud.service -n 80 --no-pager
curl --fail --silent --show-error http://127.0.0.1:8766/health
```

正常启动的服务应显示 `active (running)`，健康接口应返回 `ok: true`。模型就绪状态、健康助手版本等字段分别核对[升级验收要求](部署与升级.md#更新后的核对顺序)，不能凭服务启动就认定分析或真实采集成功。服务来自源码包时可能没有 `.git`，不要用无法读取的 Git 提交推断线上版本；以部署记录中的提交、包摘要和服务检查结果共同确认。

若出现“找不到服务”或无法连接用户服务总线，先核对 Linux 用户及会话，再由维护人员确认运行方式。不要为了消除报错临时安装第二个服务、改用系统级服务或启动另一份程序。日志可能含账号、设备或请求信息，反馈时只摘取已脱敏的错误、时间、版本和请求编号，不上传整份日志或真实心电数据。

## 共同开发与部署交接

1. 在 Issue 写明目标、预计文件及验收条件，检查现有任务是否重叠，使用独立分支和工作目录。按[贡献流程](../../CONTRIBUTING.md#每个任务的操作)提交 PR，并运行对应检查。
2. 由 XiongBoT 审核并决定合并；代理合并前必须取得对 PR 当前 HEAD 提交的明确确认，新增提交后需重新确认。合并不等于授权上线，服务器变更另按部署任务执行。
3. 部署前交接目标实例、审核后的提交、安装包 SHA-256、当前运行用户和目录、维护窗口、完整备份及回退办法。公开任务记录提交、摘要、验证结果和未完成项；备份实际位置、登录资料和敏感日志私下交接。
4. 按[部署前记录](部署与升级.md#部署前记录)准备隔离验证和完整备份，再按实际服务器布局升级。数据库管理创建的备份不包含程序、模型或运行配置，不能单独承担完整部署回退。
5. 按[更新后的核对顺序](部署与升级.md#更新后的核对顺序)验收，分别记录服务器、终端和安装包版本。没有实物测试的项目明确留待验证；据实更新[统一交付状态](../../docs/版本与交付状态.md)。

回退必须考虑升级后的新记录及数据库兼容性，不能直接用旧数据覆盖新数据。[数据库恢复工具](使用说明.md#服务器上的备份与恢复)仅恢复到不存在的新目录，且会撤销旧会话和设备凭据；隔离验证后再安排切换。完整回退边界见[回退与数据恢复](部署与升级.md#回退与数据恢复)。

## 常见权限和登录问题

| 现象 | 先检查什么 |
| --- | --- |
| 登录后实例列表为空 | 是否选择项目协作者身份、北京地域及正确所属账号；不要据此新建服务器 |
| `lighthouse:DescribeInstances` 无权限 | 由主账号维护人员检查协作者关联策略及地域/实例资源范围；列表权限与实例操作权限分别核对 |
| `ModifyUserPreferences`、`DescribeUserPreferences` 或 `DescribeUserQualifiedCrowdPackages` 无权限 | 属于控制台辅助操作，报错资源可能是 `*`；提供完整操作名和请求编号，由维护人员核对所需授权 |
| `DescribeBlueprints` 无权限 | 核对镜像列表的地域和 blueprint 资源范围，不能仅检查 instance 规则 |
| `cwp:DescribeMachineLoginType` 无权限 | 由维护人员核对该登录辅助查询的授权；它不是心电平台账号权限 |
| 能看到实例但终端登录失败 | 核对 OrcaTerm/TAT 对目标实例的授权、代理状态及页面要求的身份验证；列表可见不保证能执行命令 |
| `systemctl --user` 找不到服务或无法连接总线 | 核对服务所属 Linux 用户、用户会话及实际部署布局，不重复安装服务 |
| 云端能登录，但心电网页不能管理账号 | 使用独立的心电平台管理员账号；腾讯云协作者不会自动成为平台管理员 |

反馈应包含发生时间、所选身份类型、地域、目标实例、完整操作名、资源类型及请求编号；公开反馈需脱敏。由维护人员核对权限后，让协作者重新进入对应身份并验证；CAM 策略检查通过不能替代对方真实登录和操作验收。
