## 云端数据库管理（2026-11-24，已合并，待部署）

目标：管理员通过电脑或手机的云端后台，了解存储情况、查找和整理记录、执行完整性检查与备份；普通账号继续按现有归属查看自己的数据。用户已选择云端管理后台，本轮先在独立分支实现并以隔离数据验证，真实服务部署另行安排。

方案选择：沿用 FastAPI、SQLite 与原始波形分块，新增管理模块及手机/电脑自适应页面。现有系统已有数据库，不再建立平行数据库；换用 PostgreSQL 会增加数据迁移和运维步骤，当前没有证据表明需要更换。通用 SQL 管理器不能表达上传完整性、记录归属及回收站约束，因此采用面向心电业务的管理入口。具体布局和内部代码拆分由实现者确定。

第一版功能与边界：

1. 存储概览：数据库体积、磁盘可用空间、记录/采样点/数据块数量、上传中与回收站数量、表名与行数。目录占用异步扫描并注明测量时间；不把测量失败显示为零，不展示密码摘要、令牌或表内任意原始字段。
2. 记录管理：按用户、设备、日期和状态筛选与分页查看记录元信息；管理员可移入回收站、恢复。写操作记录操作者与对象，并遵守上传/分析中不可移入回收站的约束。普通用户接口的归属检查保持不变，管理列表不包含心电波形。第一版不做原始记录永久删除和自动清理；回收站明确提示仍占空间。
3. 完整性检查：后台执行 SQLite 完整性/外键检查，按数据库清单核对原始数据块的存在性、长度/格式与摘要，展示进度、发现的问题和检查范围。不会自动修改或删除坏数据；问题列表有数量上限及截断提示。
4. 备份管理：管理员启动后台备份并查看结果，备份仅保存在服务器，不提供网页下载。用户已明确选择这一权限边界，以保留现有管理员不能读取他人波形的约束。通过 SQLite 在线备份取得一致数据库快照，只复制该快照引用的不可变原始数据块；逐文件校验并生成清单，成功后原子公布。分析缓存可从原始数据重建，不列入备份内容；界面明确范围。空间不足、数据缺失或摘要错误时失败并保留原因，不公布半成品。
5. 恢复验证：提供本机/服务器命令，将通过校验的备份恢复到全新空目录，拒绝覆盖现有数据库及路径穿越；恢复后的登录会话失效、未完成后台任务不直接执行。用该目录启动隔离服务，验证账号结构、记录与波形可读取。第一版网页不提供覆盖线上数据库的恢复按钮。
6. 操作记录：保存管理任务及记录整理的操作时间、管理员编号、对象、状态和失败原因，不保存密码、令牌及原始波形。耗时任务使用独立工作进程，每个数据目录同时只执行一项管理任务，数量有界；进程重启时把中断任务明确标记为中断，可人工重新运行。

集成约定：新管理 API 限管理员且校验现有登录和 CSRF；普通用户、设备凭据及未启用账号模式均无权调用。管理页面从现有工作台进入，遇到换号、退出或过期应清空旧内容并忽略迟到响应；原采集和查看操作继续可用。只新增兼容表/索引及接口，保留记录格式和上传协议，更新接口文档、云端资源白名单和现行操作说明。

验收：旧库升级保留既有记录；管理员与普通账号权限隔离；筛选分页、回收/恢复及忙碌保护正确；损坏/缺失块被识别；备份期间继续上传时仍按快照生成可验证备份；失败不产生可下载半包；恢复到空目录后原始数据逐块一致，旧登录失效；手机和电脑布局及换号迟到响应检查通过。测试采用明确标注的合成数据，运行云端、网页和相关仓库检查；本地软件验证不代表公网容量或真实设备验收。
