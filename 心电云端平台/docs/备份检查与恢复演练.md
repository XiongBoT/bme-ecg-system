# 备份检查与恢复演练

[云端首页](../README.md) · [检查工具](../research/backup_audit.py) · [恢复实现](../database_backup.py)

管理员运行总览新增每日备份状态：关闭为提示；空间等原因受阻、超过下一计划或延迟重试时间 30 分钟为关注项。最近一次失败、最近成功时间沿用已有显示。点击处理入口进入数据库管理。接口只允许管理员，不返回备份绝对路径或计划操作者信息。

计划使用北京时间；“下次计划”按浏览器本地时区显示。所有历史备份继续保留。运行总览检查数据库任务状态，不能证明压缩包仍在磁盘上或能够恢复，需另做完整性检查。

## 只读清点与隔离恢复检查

在云端目录执行，替换为实际备份目录和已存在、空间充足的临时目录：

```powershell
python research/backup_audit.py "D:\ecg-backups"
python research/backup_audit.py "D:\ecg-backups" --verify --scratch "D:\ecg-check-temp"
python research/backup_audit.py "D:\ecg-backups" --verify --keep-newest 7 --scratch "D:\ecg-check-temp"
```

也可提供一个或多个明确的 ZIP 路径。目录只检查直接包含的 ZIP；空目录、缺失文件、损坏包、符号链接或目录联接均明确报错，退出码为 1。第一条只清点大小和 SHA-256，不声明内容完整。`--verify` 逐个在临时新目录恢复并核对清单、摘要、SQLite、原始块及点数，完成后删除临时副本，原备份不变。验证含真实账号信息的备份时，应使用仅运维人员可访问的本机临时目录。

默认保留全部。`--keep-newest 7` 仅按文件修改时间列出通过验证的较旧候选，统计候选容量，没有删除功能；复制备份会改变修改时间，所以不能把此预览直接当作正式保留策略。损坏或未验证的文件不成为候选。总 SHA-256 可与已有可信摘要对照；清单自检不是数字签名或来源认证。

每次恢复检查需要约一个备份的解压空间，加现有恢复器要求的 256 MiB 余量。检查使用已有恢复器，临时恢复副本中的登录会话及设备密钥会撤销，自动备份会关闭；不会修改正在运行的服务。正式灾难恢复仍需在新目录恢复、人工核对记录、重新发放设备凭据并确认启动路径。

## 回归与演练范围

执行 `python -m unittest discover -s tests -p test_backup_operations.py -v`，检查权限隔离、计划状态、合成数据库备份的隔离恢复、摘要不变以及缺失/损坏/链接拒绝。此检查验证软件流程，不代表生产备份已检查，也不测量生产恢复耗时。
