# 云端故障排查

[快速开始](快速开始.md) · [使用说明](使用说明.md) · [辅助工具](../tools/README.md)

先区分“当前版本没有这个功能”和“已有功能运行失败”。核对[交付状态](../../docs/版本与交付状态.md)，再选择下方现象；不要用重新建库或删除记录来解决版本差异。

## 连接、登录与分析

| 现象 | 检查顺序 |
| --- | --- |
| 网页或客户端无法连接 | 从首页核对当前 HTTPS 地址，检查网络及服务可用性；客户端连接问题不代表本地记录丢失 |
| 本地服务启动失败 | 从模块根目录运行，确认 Python 环境及 `requirements.txt`；检查端口是否占用、数据目录是否可写 |
| 账号登录失败 | 核对账号状态和平台地址；账号由管理员管理，服务器 SSH 密码不是平台登录密码 |
| 登录后没有记录 | 核对记录归属、账号、设备筛选及上传完成状态；未分配记录需管理员处理 |
| 模型显示 `not_configured` | 检查实际运行进程的 `ECG_MODEL`，模型依赖是否安装；本地与服务器的开关各自生效 |
| 健康检查 `model_result=null` | 健康检查不返回某条记录的结果；同时查看模型状态和目标会话的分析任务 |
| 模型拒绝或没有心搏结果 | 核对会话是否完整、输入来源、ADC、信号质量及上下文；模拟链路可验证上传，但不一定生成分类 |
| 手机看不到终端最新测量 | 先确认终端保存，再确认上传、设备授权和记录所属账号；终端总结不等于云端分析完成 |
| 旧脚本要求中转通道或找不到参考记录 | 这些属于历史联调工具；先看工具索引及归档说明，新克隆不包含原电脑的记录与凭据 |

## 数据库管理排查

| 现象 | 检查顺序 |
| --- | --- |
| 看不到数据库管理入口 | 确认新版服务和网页已部署，并登录有效管理员账号；普通账号和设备凭据不具备后台管理权限 |
| 占用显示未统计或不完整 | 点击“统计占用”；核对扫描时间及目录读取权限，未知不能当成零；上传期间目录仍会增长 |
| 整理记录提示409 | 等待上传、排队或运行中的分析完成；维护任务409表示同一目录已有检查/扫描/备份任务 |
| 备份失败或显示空间不足 | 查看任务错误；需留出数据库快照、归档及至少256 MiB余量；第一版不会自动删除历史备份或原始数据 |
| 完整性检查发现问题 | 根据记录和块编号核对原始来源及服务器文件；不要通过删库或删记录掩盖问题，坏块不会自动修复 |
| 任务中断或一直运行 | 服务重启或管理页再次查询会启动恢复检查；中断后重新提交。未知临时文件保留，需服务器核实；无权限或损坏数据库应先修复运行环境 |
| 恢复提示目标已存在 | 选择不存在的新目录，保留原目录；恢复后需重新登录、重发设备凭据及重新分析，不会自动替换正式服务 |

## 记录与报告排查

| 现象 | 检查顺序 |
| --- | --- |
| 找不到刚测的记录 | 核对终端和手机的账号是否一致 → 确认已保存、上传 → 重置日期／设备／来源筛选 → 刷新；无归属记录由管理员处理 |
| 新 APK 界面与文档不同 | 先看安装版本；1.0.0 与 1.0.2 导航不同，旧 APK 刷新不会替换内置页面，详见[手机指南](../../docs/手机端与安卓安装包.md) |
| “今天”没有记录，但最近上传能找到 | 快捷日期按设备记录的采集日期筛选，列表按上传登记时间排列；先取消日期筛选并核对设备时钟 |
| 显示上次数据或更新失败 | 当前保留的是以前成功读取的数据；联网后重试并核对读取时间，不把旧结果当成刚完成的分析 |
| 上传完成但分析没有结果 | 分别查看采集完整性、心搏分类和心搏与间期状态；分析条件不足或失败不等于正常 |
| 报告只有一小段波形 | 报告按当前波形窗口生成；调整窗口后重新预览，完整原始数据使用 CSV |
| CSV 保存后打不开 | 先在系统文件管理器确认保存位置；没有关联查看应用不代表保存失败 |
| 系统没有 PDF 保存选项 | 是否提供保存 PDF 由系统打印服务决定；手机端该流程仍需实机验收，完整原始数据可先用 CSV 保存 |

## 账号管理排查

以下针对已合并的新版源码，部署状态先查[版本与交付状态](../../docs/版本与交付状态.md)。详细操作见[账号管理说明](使用说明.md#管理员账号管理待部署)。

| 现象 | 检查与处理 |
| --- | --- |
| 找不到搜索、筛选或撤销登录 | 先核对是否为管理员，以及服务器是否已部署 PR #29；Android 还需更新内置页面的 APK。仓库已合并不等于当前页面已更新 |
| 创建时提示账号格式不正确或已存在 | 账号为 3–32 位字母、数字、横线、下划线，以字母或数字开头；首尾空白去除、大写转小写后仍须唯一。搜索现有账号再判断，勿反复提交 |
| 初始密码不能提交 | 检查密码是否为 5–128 个字符，两次输入是否一致；不要把真实密码写入反馈或截图 |
| 已提示创建成功，但列表未更新 | 点击“刷新”再搜索账号；刷新失败不代表创建失败，不要重复创建 |
| 新账号可以登录，却不在树莓派接收人列表中 | 在设备管理中核对该设备的用户授权，并确认账号已启用；创建账号不会自动授予所有设备采集权限 |
| 最近登录显示“未记录” | 旧系统没有保存历史时间，或账号尚无新版记录的成功登录；不代表该账号从未使用过。失败登录不会更新该时间 |
| 有效登录数与实际人数不同 | 该数统计尚未过期的登录凭证，不是在线人数或实体设备数；同一人可以有多个登录，关闭浏览器也不等于凭证立即失效 |
| 撤销后仍能再次登录 | 属于预期行为，原密码保留；若需阻止再次登录，应停用账号。若密码不应继续使用，重置密码后再核对状态 |
| 恢复账号后旧窗口仍提示登录失效 | 恢复不会复活已撤销的登录，使用当前密码重新登录 |
| 列表加载失败或登录校验失效 | 先刷新或重新登录，再核对账号/目标和当前状态；确认操作结果前不要反复重置密码或分配记录 |

## 验证工具的边界

`verify_live_capture.py --offline` 只检查本地证据，不证明线上验收通过。`verify_live_model.py` 读取已有云端结果并在本地复算；`verify_cloud_model.py` 会请求云端分析。运行前查看[工具分类](../tools/README.md)，不要把所有 `verify_` 脚本当作无副作用单元测试。

## 报告问题

提供提交编号、入口、操作步骤、错误消息以及是否本地/模拟/实体环境。使用脱敏的合成示例复现；不要上传账号数据库、访问令牌、真实记录或私钥。正式服务的升级和回退按[部署说明](../deploy/README.md)执行。
