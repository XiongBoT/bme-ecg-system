# 软件更新提醒

[使用说明](使用说明.md) · [版本与交付状态](../../docs/版本与交付状态.md) · [部署与构建](../deploy/README.md)

本功能提供新版提醒和下载入口，不自动下载、安装或刷新。源码合并后仍需部署服务端，并发布包含检查功能的 Windows／Android 包，用户端才会生效。

## 使用方式

| 入口 | 自动检查 | 手动操作 |
| --- | --- | --- |
| Windows 连接助手 | 启动时检查，每 24 小时最多自动尝试一次；检查与连接并行，不阻止打开工作台 | 在连接助手点击“检查更新”。发现新版可“查看新版”或“稍后” |
| Android | 启动或回到前台时检查，每 24 小时最多自动尝试一次；后台完成的结果待界面可见再显示 | 点击顶部“说明 → 检查更新”；“查看新版”由系统浏览器打开项目发布页 |
| 浏览器／PWA | 打开页面、重新可见、恢复联网时检查，另每 5 分钟检查；两次请求至少间隔 60 秒，页面隐藏或离线时暂停 | 出现提醒后先保存输入，再点击“更新并刷新”或“刷新更新”；已保存记录不受影响 |

Windows 启动器和服务器网页是两个独立更新对象。Android 的内置页面随 APK 更新，刷新旧 APK 不会替换其内置资源。浏览器管理页也会提示网页更新。

检查失败不会中断登录、记录浏览或导出；自动检查失败保持安静，手动检查会说明暂时无法获取版本信息。未发布、格式错误或不可用的清单不被当作“已是最新版”。已安装版本等于或高于发布版本时不提示降级。原生客户端仅保存最近检查时间，不保存账号或心电信息。

**当前已发布的 Windows 1.1.0 和 Android 1.0.0 试用包没有这个检查器。** 需要先手动安装包含本功能的新包，之后才能收到后续更新提醒。当前源码中的 Windows 1.2、Android 1.1.0 尚未发布，不能因为源码较新就提示下载不存在的安装包。

## 发布者如何维护版本

云端的 [client-releases.json](../client-releases.json) 只登记已经发布且可下载的版本。它与源码版本、网页部署版本分别维护；初始内容对应现有公开 Release，不会把本次开发分支自动宣布为新版。

1. 按当前任务授权完成服务端兼容验证、安装包构建和发布。Windows 更新程序集版本；Android 提高 `versionCode`、更新 `versionName`，正式包继续使用原签名。不要用 CI 的临时签名替换正式安装。
2. 确认项目 GitHub Release 已公开、附件可下载，记录包摘要和验证证据。
3. 更新清单中对应平台的 `version`、`url`、`notes`；Android 同时填写 `version_code`。版本使用三个非负整数，各段不超过 65535、无多余前导零。Windows 链接为项目 `desktop-v版本` 发布页，Android 为 `android-v版本` 或 `android-v版本-preview.序号` 发布页。
4. 清单通过 PR 由 XiongBoT 审核；部署时把完整新文件原子替换到应用目录。清单按请求读取，更新它不必重启服务；修改网页或程序则仍按正常部署流程重启应用。
5. 用测试安装验证“已有版本无提醒、新版有提醒、稍后继续使用、手动检查失败、下载页正确”。再更新统一交付状态，不能用软件测试代替实机验收。

清单格式错误时，该平台返回不可用，不回退到任意链接。暂时撤下某个平台提醒可将其值设为 `null`。这个文件不存凭据、密钥、账号或记录；发布页之外的地址不会被客户端打开。

## 接口与验证边界

`GET /api/updates` 是只读公开接口，定义见[接口约定](../../docs/接口约定.md#软件更新提醒)。请求不携带登录 Cookie 或设备密钥。原生请求拒绝重定向，保留正常 TLS 校验，限制响应大小与等待时间；网页仅请求同源接口。

网页标识在服务启动时由 `web/` 内文件路径和内容计算，并嵌入当前 HTML。客户端比较页面原始标识与服务器返回标识，避免把第一次检查时的新版错误当成旧页面基线。部署时应整体更新资源并重启服务；不支持运行中零散改写网页文件而不重启。

现有自动化检查覆盖接口隔离、版本比较、受信任链接、超时和大小限制、生命周期、节流及主动刷新。Windows／Android 的真实安装、系统弹窗、不同设备和网络下的体验仍需实机验证。任务与待合并状态见 [#49](https://github.com/XiongBoT/bme-ecg-system/issues/49)。
