# 历史趋势查询与性能验证

[健康助手](../../docs/心电健康助手.md) · [趋势接口](../health_routes.py) · [回归测试](../tests/test_trend_query.py)

日、月、年趋势继续按本人记录的采集开始时间统计；只计已上传完成、未回收的串口记录。心率按终端合格窗口采样点数加权，缺失心率不补零。时区偏移、月末与闰年口径保持不变。

服务启动时建立 `sessions_owner_started_serial_complete` 部分索引，按账号和采集时间范围定位记录。时间仍由 SQLite `julianday` 转换，避免带不同时区偏移的 ISO 时间被错误地按文字排序。索引随完成、归属和元数据变更维护，不缓存个人结果，不改写原始记录。首次升级会建立索引，应在维护窗口内检查建索引耗时与磁盘空间；后续启动复用已有索引。

在云端模块目录执行：

```powershell
python -m unittest discover -s tests -p "test_trend_query.py" -v
python -m unittest discover -s tests -p "test_health_assistant.py" -v
python research/benchmark_trends.py --records 40000 --repeats 30
```

基准仅在内存数据库创建合成元数据，比较已有账号索引和新增账号/日期索引，验证结果一致，输出查询计划、索引建立耗时、预热次数和 P50/P95。不会连接生产服务或读取真实记录。结果只代表本机 SQLite 查询，不包含磁盘、HTTP、TLS、页面渲染或服务器并发容量；CI 验证索引被使用和统计正确，不用易波动的耗时阈值判断通过。
