# 部署与升级

[云端导航](../README.md) · [构建工具](../deploy/README.md) · [版本与交付状态](../../docs/版本与交付状态.md) · [管理员指南](../../docs/管理员指南.md)

本页说明当前主分支的交付顺序。首次安装、历史 SSH 中转和 HTTPS 配置保留在原部署文件中；旧文档的日期和命令不代表服务器当前版本。本次文档更新不执行服务器或设备变更。

## 先确认交付对象

| 对象 | 构建或操作入口 | 更新后影响 |
| --- | --- | --- |
| 云端服务与网页 | 从云端模块运行 `python deploy/package_cloud.py`；[Linux 初装](../deploy/linux/部署说明.txt)、[HTTPS 配置](../deploy/linux/手机公网访问说明.txt) | API 与浏览器/PWA 页面；Windows 打开的网页也随服务器更新 |
| 树莓派完整终端 | 从终端模块运行 `python tools/package_cloud_workspace.py`；[板端准备与回退](../../树莓派心电终端/docs/设备待机与日常使用.md#启动与部署准备) | 采集、远程请求、心跳和上传；保留数据与设备凭据 |
| Android | 从 android 目录按[构建说明](../android/README.md)执行 | 随包网页和原生能力；需原签名和递增版本编号 |
| Windows 启动器 | 从云端模块运行 `python deploy/package_desktop.py`；[桌面工程](../deploy/desktop/README.md) | 启动器本身；构建不会部署网页 |

当前 Android 1.1.0（4）和 Windows 1.2.0 已公开提供试用下载，摘要见[统一状态页](../../docs/版本与交付状态.md#当前可以下载什么)。发布包不代表服务器、终端或更新清单已部署。云端应先提供健康助手接口，再升级终端与 APK；只安装 APK 不能补齐旧服务或旧终端能力。数据库管理、账号管理、任务中心等网页功能同样需要相应服务端。

## 部署前记录

记录已审核提交、包 SHA256、当前服务及数据目录、备份位置、回退版本、维护时间和操作者。确认维护窗口内没有正在进行的测量或未完成保存；不要用旧源码和新源码同时处理同一数据目录。

保留程序、运行配置、模型、完整数据及必要的分析缓存备份。数据库管理里的服务器备份仅包含数据库和引用的原始块，不能替代完整部署回退备份。备份必须可读取、可校验，并先明确如何恢复。

先在隔离数据目录启动待部署版本，检查依赖和接口，再按现有服务器布局升级。历史 `update_desktop.py` 面向其对应部署布局，使用前阅读参数和目录约束；不把任何旧升级脚本当成通用一键覆盖工具。

## 账号和设备初始化

只在首次部署且尚无管理员时，由服务器维护人员在云端模块目录执行以下示例，替换为实际数据目录及账号名：

```sh
.venv/bin/python manage_accounts.py --data-dir /实际数据目录 create-user ecgadmin --admin
```

账号名须符合格式要求，密码通过隐藏输入提供，不写在命令参数里。当前服务验证 5–128 个字符；该命令行工具仍保留“至少 10 个字符”的旧提示，使用至少 10 字符可同时满足提示与校验。它是服务器维护工具，不是从网页读取已有密码的入口。既有管理员无需重复创建，项目不提供通用初始密码。

在开放公网前，按[HTTPS 配置](../deploy/linux/手机公网访问说明.txt)启用账号认证和 Secure Cookie，验证匿名记录接口返回 401，原始服务只监听回环地址。设备在管理员页面登记并分配普通用户授权，每台终端持有独立凭据；配置步骤见[终端账号与归属](../../树莓派心电终端/docs/云端账号与记录归属.txt)。

## 更新后的核对顺序

1. 服务启动及 `/health` 返回成功；健康助手应包含 `health_assistant_version=1`。模型是否就绪单独看模型状态，不能仅凭健康检查认定分析成功。
2. 两个专用测试账号验证登录、退出、换号和各自记录隔离；管理员能进入管理页，普通账号与设备身份不能调用管理接口。
3. 验证申请→审核→设备授权，终端能取得对应接收人；设备心跳包含实际版本和就绪信息。
4. 分别验证 1／3／5 分钟采集、提前停止、上传完成、分析和报告。手机关闭不停止采集；无有效数据时结果须明确未知或条件不足。
5. 测试任务偏好默认关闭、后续首次完成上传的自动分析、任务重试及复核过期；不对真实用户记录做试验。
6. 在目标手机验证同签名升级、记住/清除密码、修改密码、CSV、系统 PDF、后台恢复和断网；Windows 验证实际窗口及连接。
7. 记录服务端、终端及客户端各自的版本、结果和未完成项，更新统一交付状态。软件测试不代替这些实机记录。

趋势按采集时间和页面 UTC 偏移统计；设备时钟须核对。运行概况的今日登记使用北京时间云端登记日，两种数字不必相同。

## 回退与数据恢复

回退前停止新服务及终端远程测量线程，确认没有进行中的采集；按预先保存的版本和数据库兼容方案恢复。不能在公网保持开放时关闭账号隔离，也不能用升级前数据直接覆盖升级后新收到的记录。

数据库备份恢复是独立操作：`tools/restore_database.py` 只接受尚不存在的目标目录，不自动替换线上服务。恢复后旧会话、设备密钥、自动分析意图和活动测量请求失效；先隔离检查账号与原始记录，再重发设备凭据并安排切换，分析和人工复核另行恢复。详见[恢复步骤](使用说明.md#服务器上的备份与恢复)。

完成后更新[发布记录](../../docs/协作质量与发布.md)要求的提交、包摘要、验证和回退信息；只有公开 Release 中的安装包才记为已发布。发布附件核验成功后，再按[更新提醒](更新提醒.md#发布者如何维护版本)更新 client-releases.json；不要先把尚未可下载的构建登记成新版。
